# Разбор эталонного приложения

## Сначала правила, затем инфраструктура

Book создаётся только в корректном состоянии: текст обрезан по краям, диапазоны проверены.
Отдельный проход по UTF-16 отвергает непарные суррогаты в названии и авторе,
чтобы JSON не заменил допустимое моделью значение на U+FFFD. Корректная пара проходит проверку.
Свойства доступны для чтения; AsRead возвращает новую запись или тот же уже прочитанный объект.
LibraryCatalog владеет списком, а наружу отдаёт массив-снимок.
Поэтому изменение полученного массива не меняет внутренние книги.

При добавлении объект Book проверяется до увеличения NextId.
Если год или название неверны, каталог не меняется и ID не расходуется.
Удаление не уменьшает NextId. При загрузке конструктор проверяет повтор ID и отношение max(Id)<NextId.

## DTO не заменяет предметную модель

JsonLibraryStore читает Snapshot и BookDto. Сериализатор проверяет синтаксис и типы JSON,
а конструкторы модели — смысл значений. Эти уровни проверок различаются:
корректный JSON с отрицательным ID всё равно является неправильным каталогом.

Отсутствующий файл обрабатывается отдельно от некорректного JSON.
Только FileNotFoundException/DirectoryNotFoundException при открытии дают пустой каталог.
Ошибочный JSON и ошибочные поля превращаются в InvalidDataException, сохраняя внутреннюю причину.
Ограничение 1 МиБ проверяется до чтения и во время накопления.

## Сохранение и подтверждение

Сначала получаются байты нового документа. Существующий файл ещё не затронут.
Далее временный файл пишется в той же папке; после успешной записи выполняется File.Move с заменой.
Путь временного файла уникален, cleanup стоит в finally.
Сохранение может отказать — поэтому CliApplication выводит «Добавлена» только после await SaveAsync.

Схема не решает конкуренцию двух писателей. Два запуска могут оба прочитать старую версию и
перезаписать результат друг друга. Для следующего этапа нужны блокировка либо проверка версии;
в рамках этого курса ограничение явно зафиксировано в SPEC.md.

## Проверяемая граница CLI

CliApplication принимает фабрику ILibraryStore, TextWriter вывода и TextWriter ошибок.
Это позволяет проверить команды без открытия консоли и без глобального Console.SetOut.
Разбор формы команды выполняется до LoadAsync.
Неизвестный ID даёт код 3 без SaveAsync; предметная ошибка аргумента — код 2.
Файловая ошибка и повреждённые данные — код 1, отмена — 130.

Настоящая точка входа короткая: включает UTF-8, создаёт CancellationTokenSource,
обрабатывает Ctrl+C и передаёт зависимости. Она не дублирует бизнес-правила.

## Что доказывают тесты

CatalogTests проверяет инварианты, границы, защиту списка, поиск и повторные операции.
StoreTests создаёт отдельную временную папку: сохранение/загрузка, повреждённые документы,
нумерация после удаления и отмена до записи.
CliTests подставляет память, считает вызовы и проверяет вывод и коды.
Дополнительный сценарий tools/cli_smoke.py запускает настоящие отдельные процессы,
поэтому данные должны пережить их завершение.

Даже вместе эти проверки не доказывают поведение при любом аппаратном сбое,
одновременной записи и на любой файловой системе. Такие свойства не заявлены.
В ходе самостоятельной реализации тесты должны оставаться связанными с контрактом,
а ожидаемые значения нельзя менять только ради успешного прогона.
