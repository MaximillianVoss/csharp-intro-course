# Итоговый проект: «Каталог книг»

## Результат и границы

Разработайте консольное приложение для одного пользователя: каталог книг хранится в одном JSON-файле.
Обязательны добавление, список, поиск, отметка о прочтении, удаление и статистика.
Каждый запуск выполняет одну команду и завершается; следующий запуск загружает тот же файл.
Это учебное локальное приложение без сетевого сервера, авторизации и базы данных.

Проект объединяет методы, коллекции, классы, интерфейсы, валидацию, исключения, JSON, LINQ,
асинхронный ввод-вывод и тестирование. Работа с файлами асинхронная, вычисления в памяти обычные:
Task.Run для сортировки маленького каталога здесь не нужен.

## Модель

Книга имеет:

| Поле | Правило |
| --- | --- |
| Id | Положительный int, уникальный в каталоге |
| Title | После Trim от 1 до 120 элементов UTF-16, без управляющих знаков |
| Author | После Trim от 1 до 80 элементов UTF-16, без управляющих знаков |
| Year | Целое от 1450 до 2100 включительно |
| IsRead | bool; новая книга не прочитана |

Одинаковые названия и авторы допустимы: различать книги помогает ID.
NextId начинается с 1, строго больше всех существующих ID и не уменьшается при удалении.
При NextId=int.MaxValue добавление отклоняется; переполнение не допускается.
Публичное чтение списка не должно позволять изменить внутреннее состояние в обход методов.

Годы и пределы длины являются учебными правилами этого проекта.
Они не претендуют на полное библиографическое описание или подсчёт видимых графем.
Title и Author должны содержать корректный UTF-16: непарные high/low surrogate отклоняются
с ArgumentException до изменения каталога и NextId. Корректная суррогатная пара допустима
и занимает две единицы UTF-16; сохранение и загрузка обязаны сохранять такой текст точно.

## Команды

Общая форма: `[--data путь.json] команда аргументы`.
Без --data используется `data/library.json` относительно текущего каталога.
Строки с пробелами заключаются в кавычки средствами оболочки.

| Команда | Аргументы | Результат |
| --- | --- | --- |
| help | нет | Краткая справка, файл не читается |
| add | название, автор, год | Новая книга; вывод её ID после успешного сохранения |
| list | нет либо --unread | Книги по возрастанию ID; фильтр непрочитанных |
| search | непустой фрагмент | Поиск в названии или авторе, OrdinalIgnoreCase |
| read | положительный ID | Отметить прочитанной; повторная отметка успешна |
| remove | положительный ID | Удалить существующую книгу |
| stats | нет | Количество всего, прочитанных, непрочитанных |

Пустой список и поиск без совпадений выводят «Книг нет.».
Пустой или пробельный запрос поиска — ошибка аргумента.
Неизвестный ID не меняет каталог. Повторное удаление возвращает «не найдено».
Неверный набор аргументов отклоняется до обращения к хранилищу.

Коды завершения: 0 — успех; 1 — ошибка файла, данных или исчерпание ID;
2 — неверная команда/аргументы; 3 — неизвестный ID; 130 — отмена.

## Формат JSON

```json
{
  "schemaVersion": 1,
  "nextId": 2,
  "books": [
    { "id": 1, "title": "Азбука", "author": "Автор", "year": 2000, "isRead": false }
  ]
}
```

Свойства используют camelCase; имена при загрузке чувствительны к регистру.
Требуются schemaVersion=1, положительный nextId и ненулевой books.
Каждая книга проверяется по правилам модели; null-элемент и повтор ID недопустимы.
Неизвестные дополнительные поля игнорируются. Отсутствующий isRead соответствует false;
изменение этой политики требует новой явно описанной схемы.

Файл до 1 МиБ, UTF-8. Отсутствующий файл означает новый пустой каталог и не создаётся командой чтения.
Пустой, повреждённый или семантически неверный файл означает ошибку; его нельзя молча заменить пустым.
Значение nextId проверяется даже у пустого каталога.

## Сохранение

Сначала сериализуется корректный снимок, затем байты пишутся во временный файл рядом с целевым.
После завершения записи выполняется замена целевого файла. При обычной ошибке или отмене
временный файл очищается; подтверждение пользователю появляется только после сохранения.
Тест отмены до начала записи должен доказывать неизменность прежних байтов.

Учебный вариант предназначен для одного процесса записи. Блокировки от двух одновременных запусков,
восстановление после отключения питания и резервное копирование не реализованы.
Замена файла уменьшает риск частично записанного JSON, но не является универсальной
гарантией транзакции при любом сбое файловой системы.
Момент замены — граница фиксации: отмена, пришедшая после неё, не откатывает сохранённое состояние.

## Структура решения

- «Библиотека.Ядро» — Book, LibraryCatalog, ILibraryStore, JsonLibraryStore, CliApplication.
- «Библиотека.Консоль» — точка входа, UTF-8 вывода, обработка Ctrl+C.
- «Библиотека.Тесты» — MSTest: модель, файловая интеграция, CLI с двойником хранилища.

Ядро не обращается к Console напрямую. CliApplication получает TextWriter и фабрику хранилища,
поэтому тест может подставить память и локальный строковый вывод.
Проект CLI ссылается на ядро; тесты тоже ссылаются на ядро; обратных ссылок нет.
