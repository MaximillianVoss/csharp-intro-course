# Разнообразие и содержательная проверка

## Объём и покрытие

Курс построен как 16 модулей по 15 задач, всего 240.
В каждом модуле пять базовых, пять прикладных и пять повышенных задач.
Форматы: реализация, чтение кода, поиск ошибки, рефакторинг, проектирование тестов и прикладная задача.
Полный каталог позволяет проверить распределение по ID, а не только заявленное количество.

В локальном расширенном C++-образце заявлено 650 задач. Здесь выбран меньший объём:
C# имеет собственную последовательность тем, а каждая новая задача должна давать отдельное действие или наблюдение.
Перенос указателей, ручного владения памятью и CMake как обязательных начальных тем исказил бы маршрут C#.
Число 240 не включает вопросы самопроверки и этапы итогового приложения.

## Критерий различия

Сравниваются звенья: название → полный контракт → проверяемый навык → алгоритм/объяснение → предметная заготовка → исполняемые проверки.
Различное имя, сюжет, константа или порядок фраз сами по себе не создают новую задачу.
Повторение синтаксиса допустимо при другом наблюдаемом навыке:
например, ранее ученик вычисляет выражение, а позднее строит регрессионный тест, ловящий переполнение до преобразования типа.
Такая связь должна быть объяснена, а тесты — действительно различаться.

Каждая запись tasks.json хранит skill и algorithm, полное условие с примерами,
разбор, типичную ошибку и список фактически реализованных проверок.
Исходник находится в отдельном TaskNN.cs, поэтому можно сопоставить метаданные и поведение.

## Автоматический отбор и ручной просмотр

Инструмент нормализует числа и строковые литералы условий, сравнивает текст,
а через Roslyn — структуру методов с обезличенными идентификаторами и литералами.
Также используется описание алгоритма. Он обнаруживает возможные кластеры,
но не объявляет любую похожую форму метода смысловым дублем.

Каждая подозрительная пара получает отдельное решение в SEMANTIC_REVIEW.json:
какие входы/преобразования или учебные результаты различаются и чем отличаются проверки.
Решение связано с fingerprint исходников; после содержательного изменения старое разрешение не действует.
Кандидаты, признанные повторами, должны быть заменены в авторском источнике,
а не скрыты переименованием заголовка.

Актуальные результаты выполнения аудита сохраняются в artifacts/audit.json.
Числа успешных запусков и проверенный коммит фиксируются в RESULT.json.

## Решения по сходству

При подготовке были заменены три содержательных повтора:

- 04-14: повтор списания со счёта заменён переносом времени через полночь с двумя ref и неизменностью обоих значений при отказе.
- 12-07: повтор удаления дублей заменён ограниченным переносом между вариантными ISource/ISink с проверкой точного числа чтений.
- 12-08: повтор поиска максимума заменён созданием независимых экземпляров через ограничение class, new().

При подготовке 17 октября автоматический отбор оставил три пары для ручного решения.
В редакции 19 октября все три повторно сопоставлены; окончательный отбор также
отмечает эти три пары. Для каждой подтверждены различия контрактов и проверок:

| Пара | Существенное различие |
| --- | --- |
| 07-03 / 07-07 | Все уникальные элементы одного входа через Add / пересечение двух входов через потребляющий Remove |
| 07-03 / 07-10 | Удаление повторов / фильтр по внешнему набору с сохранением повторов запросов |
| 07-07 / 07-10 | Remove допускает значение один раз / Contains сохраняет каждое разрешённое вхождение |

В SEMANTIC_REVIEW.json приведены различающие входы и результаты для каждой пары.
Совпадение формы цикла не отменяет различия состояния множества и кратности результата.
Повторное применение ранее изученного алгоритма на новом механизме явно объясняется:
например, generic binary search в 12-12 закрепляет инвариант поиска и ограничения типов.
Такое закрепление не выдаётся за новый алгоритм.

Автоматический порог не доказывает отсутствие всех возможных смысловых повторов.
Он дополняется авторской проверкой каждого контракта и независимым просмотром материалов;
границы независимого просмотра указаны в [отчёте](INDEPENDENT_REVIEW.md).
