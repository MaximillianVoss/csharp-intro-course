# Visual Studio

Для .NET 10 используйте актуальную **Visual Studio 2026**.
Microsoft указывает минимальное семейство Visual Studio 2026 18.0+ для SDK 10;
конкретный новый feature band SDK может требовать обновления IDE.
Проще обновить IDE через Visual Studio Installer и установить рабочую нагрузку **Разработка классических приложений .NET**.
Официальная [таблица совместимости](https://learn.microsoft.com/en-us/dotnet/core/install/windows#net-versions-and-visual-studio).

## Открытие

1. Файл → Открыть → Проект или решение.
2. Выберите «Курс CSharp.slnx» в корне.
3. Дождитесь восстановления зависимостей.
4. В обозревателе решения найдите «Урок01.Примеры».
5. Нажмите правой кнопкой → Назначить запускаемым проектом.
6. Ctrl+F5 запускает без отладчика; F5 — с отладкой.

Решение «Практика CSharp.slnx» содержит только проекты «Заготовки».
Оно удобнее ученику, который хочет работать без открытых готовых исходников.
Ответы при этом физически остаются в репозитории: это учебное разделение, а не защита от просмотра.

## Выбор задачи

В свойствах запуска проекта/профиле отладки задайте аргументы командной строки `01-01`
(для выбранного урока используйте его ID). `--list` выводит список, `--all` запускает все.
Без аргументов решения проверяют все задачи, а заготовки показывают список.
Редактируйте Task01.Run и добавляйте методы внутри класса Task01.

## Пошаговая отладка

На цикле из урока 3:

1. Поставьте точку останова F9 до первого изменения накопителя.
2. Запустите F5 с конкретным ID.
3. Добавьте индекс и накопитель в Watch/Контрольные значения.
4. До F10 запишите прогноз следующего значения.
5. F10 выполнит строку без входа в метод; F11 позволит войти в свой метод.
6. Проверьте последний допустимый индекс и условие выхода.
7. Если возникает ошибка, посмотрите Call Stack/Стек вызовов, а не только текст всплывающего окна.

Для исключений откройте Debug → Windows → Exception Settings.
Остановка в момент выбрасывания помогает отличить исходную причину от места окончательной обработки.
Отладчик при этом может остановиться и на исключении, которое тест ожидает специально.

## Тесты

Test → Test Explorer → Run All Tests запускает MSTest проекта «Библиотека.Тесты».
Встроенные проверки 240 учебных решений являются консольными проверками Check, а не MSTest-тестами;
их запускают через выбранный проект или общий скрипт.
Это различие объясняется в уроке 16.

## Диагностика открытия

Если IDE не понимает .slnx или net10.0, обновите Visual Studio; не меняйте TargetFramework на .NET Framework.
CLI-путь из ENVIRONMENT_SETUP.md остаётся самостоятельным способом сборки.
Проверка открытия окон IDE и работа команд dotnet — разные виды проверки; фактический статус см. VERIFICATION.md.
