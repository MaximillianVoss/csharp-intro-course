# Проверка курса

## Воспроизведение

Из корня, с .NET SDK 10 и PowerShell 7:

```powershell
pwsh -NoProfile -File tools/Verify.ps1
```

Скрипт восстанавливает зафиксированные зависимости, собирает Release с предупреждениями как ошибками,
запускает MSTest итогового проекта, каждый пример и все 240 решений.
Для каждой задачи требуется исполняемый Run; итоговое число задач и проверок извлекается из результата программы.
Заготовки собираются и показывают каталог; их самостоятельные тела не объявляются выполненными.

Проверки содержания и отдельные процессы CLI требуют Python 3.11+ (стандартная библиотека, без установки пакетов):

```powershell
python tools/render_course.py --check --strict
python tools/cli_smoke.py
python tools/audit_course.py
```

Если команда python указывает на неработающий системный псевдоним, используйте полный путь к своему Python.
Для обычного прохождения уроков Python не нужен.
Параметр --discover создаёт кандидаты аудита и допускает ещё неразобранные пары;
такой запуск сам по себе не является успешной приёмкой содержания.

## Что сохраняется

В игнорируемом каталоге artifacts создаются:

- verification.json — SDK, платформа, сборка, MSTest, модули и фактические assertions;
- TestResults/capstone.trx — машиночитаемый результат MSTest;
- example-NN.log, solutions-NN.log, templates-NN.log — вывод каждого проекта;
- cli-smoke.json — отдельные запуски настоящей CLI;
- audit.json — контракты, статистика, синтаксические fingerprints и подозрительные пары.

Фиксация опубликованного результата и проверенного SHA сохраняется в RESULT.json и комплекте сдачи.
Тесты могут не покрывать весь допустимый диапазон; число assertions не заменяет анализ выбранных сценариев.

## Как устроен аудит

render_course.py --check сравнивает TASKS.md и SOLUTIONS.md с tasks.json и актуальными C#-исходниками,
поэтому изменение условия без изменения публикуемого Markdown будет обнаружено.
audit_course.py проверяет структуру каталога, ссылки, уровни, форматы и наличие проверок.
С помощью Roslyn из установленного SDK он сравнивает структуру методов:
идентификаторы и значения литералов нормализуются, операторы и форма управления сохраняются.
Дополнительно сравниваются нормализованные условия и описание алгоритма.

Высокое сходство не доказывает дубль. Кандидат просматривается вместе с условием, решением и тестами.
Решение в docs/SEMANTIC_REVIEW.json содержит конкретную причину и fingerprint обоих заданий.
Изменение этих исходников отменяет прежнее решение аудита: его нужно проверить заново.
Нельзя автоматически разрешать все пары одной общей формулировкой.

## Генерация

```powershell
python tools/render_course.py --strict
python tools/render_course.py --check --strict
```

Генератор оформляет каталог и проектный каркас.
Авторские TaskNN.cs не генерируются и не затираются, поэтому содержательные исправления сохраняются.
Существующий templates/Tasks.cs также не перезаписывается — это место самостоятельной работы.

## Чистая копия и платформы

Проверка после публикации должна клонировать GitHub-репозиторий в новый каталог,
сверить SHA, повторить команды и убедиться, что tracked-файлы остались неизменными.
Проверенный локальный запуск, GitHub Actions и ручная работа в окне Visual Studio — разные свидетельства.
Конкретные пройденные среды и ограничения фиксируются в итоговом RESULT.json.
Код использует переносимые API, но без фактического запуска платформа не объявляется проверенной.

GitHub Actions выполняет эти команды для Windows и Ubuntu, сохраняя artifacts.
Зелёный статус учитывается только после завершения запуска для нужного коммита.
