# Оценивание

## Одна задача: 10 баллов

| Критерий | Баллы | Как проверить |
| --- | --- | --- |
| Соответствие контракту | 0–4 | Нормальные входы, точный выход, оговорённые отказы |
| Границы и проверка | 0–2 | Различающие случаи, а не повтор примера |
| Понятность решения | 0–2 | Имена, декомпозиция, отсутствие ненужного состояния |
| Объяснение | 0–2 | Ученик прослеживает код и объясняет выбор |

Для чтения кода оцениваются вывод, трассировка и причина.
Для поиска ошибки — воспроизведение, исправление и регрессионный тест.
Для рефакторинга — сохранение поведения и улучшенная граница ответственности.
Для тестирования — набор случаев должен отличать правдоподобную неправильную реализацию.

Задание без существенного поведения получает максимум 3/10, даже если компилируется.
Просмотр эталона допустим после попытки; при сдаче требуется объяснение собственного кода и новое изменение.

## Контроль модуля

Выберите минимум 8 задач: 3 базовые, 3 прикладные, 2 повышенные.
В набор должны входить реализация, чтение/поиск ошибки, рефакторинг и тестирование.
Модуль освоен при среднем результате от 7/10 и успешной короткой защите.
При среднем от 5 до 6.9 назначьте адресную доработку слабого навыка; ниже 5 вернитесь к примеру и трассировке.
Оценка не зависит от того, выбраны ли случайно самые короткие задачи.

## Итоговое приложение: 100 баллов

| Критерий | Баллы |
| --- | --- |
| Модель, инварианты, уникальные ID | 15 |
| Все команды и проверка аргументов | 20 |
| JSON, повторный запуск, отказ без порчи файла | 20 |
| Структура решения и заменяемые зависимости | 10 |
| Различающие модульные и интеграционные тесты | 15 |
| Отладка и объяснение причины ошибки | 10 |
| Инструкция запуска и самостоятельное изменение на защите | 10 |

Готовность к защите требует: успешную сборку, тесты без пропусков, все обязательные команды,
сохранение после перезапуска и понятный отказ на повреждённом JSON.
При отсутствии хранения данных итог ограничивается 59/100; при невозможности самостоятельного запуска — 49/100.
Это учебная шкала курса, а не нормативные требования конкретного учебного заведения.

От 85 — уверенное владение, 70–84 — самостоятельная база с отдельными недочётами,
60–69 — требуется доработка, ниже 60 — обязательная часть не завершена.
Требование объяснить код и выполнить изменение остаётся при любом количестве зелёных тестов.

## Сценарий защиты

1. Получить чистую копию и назвать SDK.
2. Собрать решение и запустить MSTest.
3. Добавить две книги; закрыть программу и показать повторную загрузку.
4. Найти по фрагменту, отметить прочтение, вывести статистику.
5. Удалить книгу; показать, что новый ID не переиспользован.
6. Показать ошибки аргумента, неизвестного ID и повреждённого файла.
7. Добавить один различающий тест и выполнить небольшое изменение.

Возможные изменения на защите: фильтр по году, сортировка по автору, новая статистика.
Сначала ученик уточняет контракт: регистр, пустой результат, равные ключи и поведение старых данных.
