## Подтверждённые замечания и повторная проверка

### IR-01 — P2: недостающая ссылка в заготовке 16-15 — устранено

Место: `lessons/lesson_16_testing_project/templates/Урок16.Заготовки.csproj`, `tools/render_course.py`, условие 16-15.

Условие обещало уже настроенную ссылку на `Библиотека.Ядро`, однако генератор исключал заготовки из добавления `ProjectReference`. Обращение ученика к `Course.Library.CliApplication` не компилировалось. На копии настоящего проекта с заменой только относительных путей на абсолютные получена ошибка CS0234.

Исправление: ссылка добавлена и в заготовки модуля 16; соответствующая ветвь генератора исправлена. Повторно прочитанный реальный проект, скопированный в изолированный пробник, успешно собран с обращением к `CliApplication`, Release и предупреждениями как ошибками: 0 ошибок, 0 предупреждений.

### IR-02 — P2: конвертер enum принимал запрещённые строки 11-13 — устранено

Место: `lessons/lesson_11_json/solutions/Task13.cs`, метаданные и условие 11-13.

Исходное `Read("\"Pending, Done\"")` возвращало `Done`. Так же принимались `"Done, Done"`, `"Pending, Pending"` и `" done "`, хотя контракт разрешал только отдельные имена Pending/Done с произвольным регистром. `allowIntegerValues:false` само по себе не сужало грамматику до этого требования.

Исправление: чтение требует JSON-строку и точно сравнивает её значение с двумя разрешёнными именами через `OrdinalIgnoreCase`. Запись по-прежнему использует конвертер и проверяет определённость enum. Независимый пробник подтвердил отказ на составных/пробельных именах и успешное чтение смешанного регистра; пробелы вне JSON-строки остаются допустимы.

### IR-03 — P3: обещание любого UTF-16 для точного JSON round trip 11-09 — устранено

Место: `lessons/lesson_11_json/solutions/Task09.cs`, условие и объяснение 11-09.

Для исходного допустимого по формулировке `"\uD800"` операция BuildMessage → JsonDocument.GetString возвращала U+FFFD вместо U+D800. Условие «любые строки» противоречило обещанию точного восстановления входа.

Исправление: контракт задаёт корректную последовательность UTF-16, а непарные суррогаты отклоняются `ArgumentException` до записи. Проверен проход по парам в исходнике. Независимые проверки охватили одиночные старший/младший суррогаты и неверные сочетания, корректные emoji, комбинируемый акцент, NUL, CR/LF, кавычки и обратную косую черту. Корректные значения восстанавливаются без нормализации.

### IR-04 — P3: неоговорённое совпадение stock и request в 07-08 — устранено уточнением контракта

Место: условие 07-08 в `lessons/lesson_07_collections/tasks.json`.

При передаче одного словаря в оба параметра `TryReserve(d,d)` успешно уменьшал значения request, хотя условие требовало request сохранить. Одновременно изменять stock и сохранять request при их тождестве невозможно. Это была недоговорённость предусловий, а не ошибка двухфазного алгоритма на разных словарях.

Исправление: явно указаны разные экземпляры словарей. Независимый пробник на разных словарях подтвердил успешное списание и неизменность request.

### IR-05 — P2: допустимый маленький делитель приводил к переполнению 02-15 — устранено

Место: `lessons/lesson_02_input_conditions/solutions/Task15.cs`, условие и reasoning 02-15.

`Calculate("1000000","/","0.0000000000000000000000000001")` бросал необработанный `OverflowException`. Обе строки разбирались в decimal, длины были меньше 100, значения удовлетворяли заданному диапазону. В объяснении ошибочно утверждалось, что остальные операции после ограничения операндов также укладываются в decimal.

Исправление: определён ответ `overflow`, обрабатывается переполнение расчёта; объяснение исправлено. Проверено, что исходный контрпример даёт `overflow`, а допустимое `1 / 1e-28` возвращает точный текст большого частного. Просмотрены тесты обеих ветвей и приоритеты ошибок.

### IR-06 — P3: порядок округления чека 04-07 был раскрыт только в решении — устранено

Место: условие 04-07 в `lessons/lesson_04_methods/tasks.json`.

Для цены 0.01 и количества 15 округление скидки до вычитания даёт итог 0.13, а округление исходной разности 0.135 даёт 0.14. Ранее условие требовало только округлить денежные значения; нужный порядок объяснялся после открытия ответа.

Исправление: условие явно требует сначала округлить скидку AwayFromZero и затем вычесть уже округлённое значение. Это независимо сверено с решением и существующим различающим тестом 0.01 × 15.

### IR-07 — P2: разрешённая модель книги теряла UTF-16 при сохранении — устранено

Место: `capstone/Библиотека.Ядро/Book.cs`, `SPEC.md`, тесты каталога и хранилища.

Реальный эксперимент: `Add("A\uD800B","Author",2000)` успешно создавал книгу; после `SaveAsync` → `LoadAsync` U+D800 превращался в U+FFFD. Правила длины и отсутствия управляющих знаков не исключали такой вход. Сохранение изменяло разрешённые моделью данные без сообщения об ошибке.

Исправление: `Book.ValidateText` отвергает непарные суррогаты, SPEC и сопроводительные документы согласованы. Проверен сам проход по UTF-16. В независимом пробнике выполнены 8 отказных случаев по обоим полям с проверкой неизменности Count/NextId и один точный файловый round trip с emoji в Title и Author: 9/9. После этого проект MSTest повторно собран и выполнен: 49/49.

### IR-08 — P2: синхронный каркас самостоятельной работы в асинхронном уроке — устранено

Место: `lessons/lesson_15_async/templates/Tasks.cs`, `templates/Program.cs`, `tools/render_course.py`, README урока 15.

Заготовки предоставляли `void Run` и диспетчер `Action`, тогда как решения урока использовали `Task` и `Func<Task>`. Ученик не мог добавить await в предоставленное рабочее место без изменения каркаса. Вариант async void возвращал бы управление диспетчеру до окончания задачи и обходил бы нормальную обработку поздних ошибок.

Исправление: 15 заготовок возвращают Task, диспетчер ожидает `Runner.RunAsync` с `Func<Task>`, генератор создаёт соответствующий каркас. README объясняет добавление async и запрет async void для этой работы. Изолированный пробник с незавершённым TaskCompletionSource доказал: диспетчер ждёт задачу; поздний IOException приводит к FAIL, `failed=1` и коду 1.

### IR-09 — P3: старые названия в комментариях заготовок — устранено

Место: комментарии перед TaskNN в `templates/Tasks.cs` модулей 04, 11 и 12.

Сравнение заголовков с текущими tasks.json обнаружило четыре несовпадения: 04-14, 11-04, 12-07, 12-08. ID и переходы к условию сохранены; тела заготовок не содержат ответов. Причина — сохранение существующих заготовок генератором после замены задач. Автор обновил только названия комментариев в новом комплекте. Независимый повторный скрипт сравнил заголовки всех 240 заготовок с метаданными: несовпадений нет. Сохранение существующей ученической работы генератором не отменено.
