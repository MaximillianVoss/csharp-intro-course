## 02-01. Четыре исхода чтения количества

Уровень 1 · Реализация · Навык: Отделение отсутствия данных от синтаксической и смысловой ошибки

Реализуйте тело каркаса `string ReadCount(string? text)`. text представляет одну строку
от Console.ReadLine; null означает EOF. Верните `eof` для null, `invalid`, если
`int.TryParse(text, out int value)` не смог прочитать целое, `range` для целого вне 0..100,
иначе `ok:N`, где N — прочитанное число без ведущих нулей.
TryParse допускает окружающие пробелы и ведущий знак; других преобразований не делайте.
Длина строки не более 100 символов; обычные ошибки ввода не должны приводить к исключению.

**Пример и ожидаемое поведение**

`ReadCount(null)` → `"eof"`; `ReadCount(" 007 ")` → `"ok:7"`; `ReadCount("101")` → `"range"`.

## 02-02. Три знака целого числа

Уровень 1 · Реализация · Навык: Взаимоисключающая цепочка if/else

Заполните `string Sign(int value)`: верните ровно `negative`, `zero` или `positive`
в зависимости от знака value. Допустим любой int. Используйте ветвления,
а не Math.Sign. Для одного вызова должен формироваться один результат.

**Пример и ожидаемое поведение**

`Sign(-1)` → `"negative"`; `Sign(0)` → `"zero"`; `Sign(1)` → `"positive"`.

## 02-03. Полуоткрытое окно приёма

Уровень 1 · Реализация · Навык: Точное включение и исключение границ интервала

Реализуйте `bool InWindow(int minute, int opening, int closing)`.
Все аргументы — минуты одних суток от 0 до 1440, причём opening <= closing.
Приём идёт на полуоткрытом интервале [opening, closing): открытие включено, закрытие исключено.
Если границы совпали, окно пусто. Ночного перехода через полночь здесь нет.
Вне предусловий вызовов нет.

**Пример и ожидаемое поведение**

`InWindow(540,540,1020)` → true; `InWindow(1020,540,1020)` → false.

## 02-06. К какому if относится else

Уровень 2 · Чтение кода · Навык: Синтаксическая привязка else и роль фигурных скобок

Дан полный метод; отступы не меняют синтаксис:
```csharp
public static string Inspect(bool ready, bool permitted)
{
    string result = "unchanged";
    if (ready)
        if (permitted)
            result = "go";
        else
            result = "denied";
    return result;
}
```
Назовите результат для всех четырёх пар ready,permitted и воспроизведите метод.
Затем добавьте скобки без изменения поведения. Все bool допустимы.

**Пример и ожидаемое поведение**

`Inspect(false,false)` → `"unchanged"`; `Inspect(true,false)` → `"denied"`.

<a id="02-07"></a>
## 02-07. Безопасный порядок короткого замыкания

Уровень 2 · Поиск ошибки · Навык: Защита операции условием слева от &&

Исправьте порядок частей метода:
```csharp
public static bool Divides(int value, int divisor)
{
    return value % divisor == 0 && divisor != 0;
}
```
value,divisor от -1 000 000 до 1 000 000. Для divisor=0 требуется false без исключения,
иначе true тогда и только тогда, когда value делится на divisor без остатка.
Вне диапазонов вызовов нет. Объясните, почему && в исходнике не защищает деление.

**Пример и ожидаемое поведение**

`Divides(12,3)` → true; `Divides(12,0)` → false; исходник при (12,0) вызывает DivideByZeroException.

## 02-08. Плоские проверки перед отправкой

Уровень 2 · Рефакторинг · Навык: Ранние возвраты с сохранением приоритета ошибок

Дан метод:
```csharp
public static string Status(bool paused, bool addressValid, bool paid)
{
    if (!paused)
    {
        if (addressValid)
        {
            if (paid) return "send";
            else return "payment";
        }
        else return "address";
    }
    else return "paused";
}
```
Перепишите его без вложенных if, сохранив все результаты, включая приоритеты при нескольких
проблемах. Все комбинации допустимы. Уберите else после безусловного return.

**Пример и ожидаемое поведение**

`Status(true,false,false)` → `"paused"`; `Status(false,false,false)` → `"address"`.

## 02-11. Испытания существования треугольника

Уровень 3 · Проектирование тестов · Навык: Проверки симметрии, вырожденности и недопустимых сторон

Нужен `bool IsTriangle(int a, int b, int c)`. Все аргументы от -1 000 000 до 1 000 000.
Для неположительной стороны верните false; иначе true только для невырожденного треугольника.
Сформулируйте и выполните тесты, которые отличают правильный метод от ошибочного:
```csharp
public static bool Wrong(int a, int b, int c)
{
    return a > 0 && b > 0 && c > 0 && a + b >= c;
}
```
Обязательно испытайте равенство суммы двух сторон третьей и перестановки длин.
Реализуйте правильный метод. Вне диапазонов вызовов нет.

**Пример и ожидаемое поведение**

`IsTriangle(3,4,5)` → true; `(1,2,3)` и `(10,1,2)` → false.

## 02-14. Переход состояния по одной команде

Уровень 3 · Реализация · Навык: Выбор команды с зависимостью ответа от предыдущего состояния

Реализуйте `string Command(bool running, string? command)` без циклов.
null → `eof`. Точный текст `start` даёт `already-running`, если running=true, иначе `started`;
`stop` даёт `stopped`, если running=true, иначе `already-stopped`; `status` возвращает
`running` или `stopped`. Любая иная строка, включая пустую, пробелы и другой регистр, даёт `invalid`.
Метод только сообщает результат одного перехода, состояние снаружи не изменяет.
Длина строки до 100; все состояния допустимы.

**Пример и ожидаемое поведение**

`Command(false,"start")` → `"started"`; `Command(true,"stop")` → `"stopped"`.

<a id="02-15"></a>
## 02-15. Один расчёт из трёх строк

Уровень 3 · Прикладная задача · Навык: Согласование EOF, разбора, диапазона и предметных ошибок

Реализуйте `string Calculate(string? leftText, string? operation, string? rightText)`.
Если хотя бы одно поле null, верните `eof`. Затем оба числовых поля разбираются как decimal
с InvariantCulture и ровно флагами `NumberStyles.AllowLeadingSign | NumberStyles.AllowDecimalPoint`:
допускаются знак и точка, пробелы, запятая и экспонента запрещены. Эти имена параметров API даны каркасом.
Ошибка разбора → `invalid`; успешно разобранное число вне [-1000000,1000000] → `range`.
Далее допустимы только точные операции `+`, `-`, `*`, `/`; другая строка → `operation`.
Деление на ноль → `zero`. Если сама арифметическая операция вызывает OverflowException,
верните `overflow`. Успех → decimal-результат через ToString(InvariantCulture), без принудительного
числа знаков. Максимальная длина поля 100; исключения не должны выходить из метода.
Для урока 02 готовый защитный каркас предоставляется преподавателем:
```csharp
try
{
    // Ваш switch, вычисление и возврат успешного результата.
}
catch (OverflowException)
{
    return "overflow";
}
```
Подробное устройство обработки исключений изучается в уроке 10; сейчас это оболочка операции.

**Пример и ожидаемое поведение**

`Calculate("1.5","+","2")` → `"3.5"`; `("4","/","0")` → `"zero"`; `("1,5","+","2")` → `"invalid"`.
