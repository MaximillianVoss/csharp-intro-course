# Модуль 06. Массивы, индексы и алгоритмы

## 1. От отдельных переменных к последовательности

К началу модуля нужны условия, циклы, методы и работа со строкой. Здесь мы учимся хранить много однотипных значений, выбирать способ обхода и объяснять корректность алгоритма. Коллекции, собственные классы и LINQ для задач этого модуля не нужны. Сначала запустите [пример](examples/Program.cs), затем выполняйте [условия задач](TASKS.md). После собственной попытки сравните подход с [разборами](SOLUTIONS.md) и запустите соответствующее решение.

Массив удобен, когда известен размер набора или важен прямой доступ по номеру. Например, показания датчика за сутки можно хранить в `int[24]`. Но смысл индекса определяет программа: индекс ноль может означать первый час, а может быть номером записи. Нельзя автоматически считать индекс самим значением. В `[10, 20, 10]` значение 10 находится на двух разных позициях.

Перед написанием метода договоритесь о четырёх вещах: допустимых входах, форме результата, обработке пустоты и праве менять источник. Контракты «вернуть индекс» и «вернуть значение» отличаются даже при одном названии поиска. В задачах входной массив обычно не `null`, но может быть пустым. Это два разных состояния: пустой массив существует, его длина равна нулю; `null` означает отсутствие ссылки на массив.

Условие задачи имеет приоритет перед удобным предположением. Если требуется первый максимум, нельзя молча возвращать последний. Если нужна независимая копия, недостаточно вернуть правильные числа, оставив общую ссылку. Хорошее решение делает эти требования заметными в именах метода, проверках и выборе сравнений.

## 2. Что создаёт new и что копирует присваивание

Запись `new int[4]` создаёт массив из четырёх элементов, каждый первоначально равен нулю. Число элементов этого объекта впоследствии не меняется. Можно изменить отдельную ячейку, но нельзя дописать пятую в тот же массив. Для другого размера создают другой объект. Переменная массива хранит ссылку; обычное присваивание копирует эту ссылку. Это свойства [массива C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/arrays).

```csharp
int[] original = { 5, 8 };
int[] alias = original;
int[] copy = (int[])original.Clone();
alias[0] = 99;
copy[1] = 12;
// original: [99, 8]; alias: [99, 8]; copy: [5, 12]
```

Проследим операции. Сначала существует один массив `[5,8]`. После присваивания `alias` у него два имени доступа. `Clone` создаёт второй массив с такими же элементами. Изменение через `alias` наблюдается через `original`, а изменение `copy` остаётся во втором массиве. Само приведение `(int[])` требуется здесь из-за типа результата библиотечного `Clone`.

Для массива `int` такая копия даёт независимые числа. Для массива массивов копируются ссылки на внутренние массивы, поэтому глубокая независимость автоматически не возникает. Позднее мы разберём то же явление на собственных объектах. Уже сейчас полезно рисовать схему: прямоугольник объекта и стрелки переменных. Схема обычно яснее слов «массив скопировался».

При передаче массива в обычный метод копируется ссылка, поэтому метод может изменить элементы общего объекта. Для этого не требуется `ref`. Однако переназначение параметра на новый массив само по себе не переназначает переменную вызывающего. Когда задача требует новую последовательность, явно возвращайте её результатом метода; когда нужна операция на месте, укажите это в контракте.

## 3. Границы и инвариант обхода

Если длина равна `n`, допустимые индексы лежат в полуинтервале `[0,n)`: от нуля включительно до `n` исключительно. У пустого массива нет ни одного допустимого индекса. Поэтому стандартный цикл использует `i < values.Length`. Условие `i <= values.Length` неизбежно пытается прочитать лишний элемент. Изменение на `i < Length-1` тоже неправильно, поскольку пропускает последний.

```csharp
static long Sum(int[] values)
{
    long total = 0;
    for (int i = 0; i < values.Length; i++)
        total += values[i];
    return total;
}
```

Для `[4,-1,7]` перед итерациями получаются состояния `(i,total)`: `(0,0)`, `(1,4)`, `(2,3)`, после последней записи — `(3,10)`. В момент проверки `3 < 3` тело больше не выполняется. Для пустого массива первая проверка уже ложна, сумма остаётся нулевой. Это не особый случай, дописанный наугад, а следствие правильно выбранных границ.

Инвариант — утверждение, сохраняющееся перед каждой итерацией. Здесь `total` равен сумме элементов с индексами меньше `i`. Сначала таких элементов нет, поэтому сумма нулевая. Одна итерация добавляет ровно очередной элемент, сохраняя утверждение. На выходе `i=n`, значит, учтены все элементы. Подобное объяснение помогает найти ошибку раньше запуска.

Тип аккумулятора выбирают по возможной сумме, а не по типу одной ячейки. Два `int.MaxValue` уже не помещаются в `int`. При ограничении длины 100000 сумма всех `int` помещается в `long`. Для среднего важно также привести сумму к `double` до деления: `(double)total / n`. Приведение после целочисленного деления не возвращает потерянную дробную часть.

## 4. Изменять источник или строить результат

Отбор положительных значений показывает, зачем нужны два прохода. В первом считаем подходящие элементы, во втором заполняем массив точной длины. Индекс чтения и индекс записи имеют разный смысл. Чтение посещает весь источник, запись продвигается только при принятом элементе. Исходный порядок сохраняется, потому что элементы никогда не переставляются.

Один проход с массивом исходной длины тоже возможен, но оставит неиспользованный хвост. Если вернуть такой массив без дополнительного размера, нули хвоста станут неотличимы от настоящих результатов. Контракт точного размера решает проблему яснее. Пустой отбор возвращает массив длины ноль, а не `null`, если условие не требует другого.

Разворот на месте использует две границы: левую и правую. Пока `left < right`, симметричные элементы меняются местами. После обмена обе границы приближаются к центру. У нечётной длины центральная ячейка остаётся на месте. У пустого массива правая граница равна `-1`, но тело не выполняется, и обращения по этому индексу нет.

Направление обхода особенно важно при перекрытии копируемых участков. Пусть нужно сдвинуть `[1,2,3,4]` вправо на одно место, заполнив начало нулём. Если идти слева направо, первая запись уничтожит двойку, затем прочитается уже записанная единица: получится `[0,1,1,1]`. Если идти справа налево, каждое исходное значение читается до перезаписи: результат `[0,1,2,3]`.

Циклический сдвиг решает другую задачу: хвост возвращается в начало. Для непустого массива сначала уменьшают шаг по модулю длины. Индекс назначения равен `(i+shift)%n`. Сначала нужна проверка пустоты, иначе остаток от деления на ноль недопустим. Не смешивайте циклический сдвиг с заполнением нулями: схожие названия скрывают разные результаты.

## 5. Поиск, сортировка и обещания о порядке

Линейный поиск не требует сортировки. Чтобы найти первый максимум, начинаем с индекса ноль и обновляем лучший индекс только при строгом увеличении значения. Сравнение `>=` выбрало бы последний максимум. Начальный «максимум равен нулю» неверен для полностью отрицательных данных. Пустой массив обрабатывают до обращения к первой ячейке.

Сортировка меняет порядок. Библиотечный `Array.Sort` полезен, когда нужен упорядоченный набор, но не является безобидной подготовкой любого поиска. После сортировки нельзя вернуть первоначальный индекс без отдельной связи между значением и исходной позицией. В задачах на порядок появления сортировка обычно нарушает контракт. Если источник должен сохраниться, сначала копируют его.

Бинарный поиск требует отсортированного массива. Для первого совпадения удобно искать нижнюю границу: первую позицию, где значение не меньше цели. Интервал поиска `[lo,hi)` сначала равен всему массиву. Если середина меньше цели, левая граница становится `middle+1`; иначе правую сдвигают в `middle`. При равенстве немедленный возврат запрещён, потому что левее могут находиться другие совпадения.

Например, в `[1,2,2,2,8]` при цели 2 сначала рассматривается индекс 2. Его значение подходит, поэтому `hi=2`. Затем индекс 1 тоже подходит, получаем `hi=1`. Индекс 0 меньше цели, поэтому `lo=1`. Границы сошлись на первом совпадении. Если цель больше всех, границы сойдутся на `Length`; перед чтением результата нужна проверка допустимости индекса.

Слияние двух уже отсортированных массивов использует другой ресурс: готовый порядок обоих источников. Два указателя выбирают меньшую из оставшихся голов. При равенстве переносится только одна голова, поэтому кратность сохраняется. Когда один источник закончился, остаток другого уже упорядочен. Каждый элемент переносится один раз, повторная сортировка не нужна.

## 6. Прямоугольные матрицы и соседство

У `int[,]` два измерения. `GetLength(0)` означает число строк, `GetLength(1)` — число столбцов. Свойство `Length` даёт общее число ячеек. У матрицы 2 на 3 оно равно шести, поэтому использовать его как число строк нельзя. Во вложенных циклах границы каждого индекса берут из соответствующего измерения.

```csharp
int[,] source = { { 1, 2, 3 }, { 4, 5, 6 } };
int[,] result = new int[source.GetLength(1), source.GetLength(0)];
for (int row = 0; row < source.GetLength(0); row++)
    for (int column = 0; column < source.GetLength(1); column++)
        result[column, row] = source[row, column];
```

Транспонирование переставляет и размеры, и координаты. Результат имеет три строки и два столбца. Проверка только на квадратной матрице не обнаруживает ошибочно оставленную форму. Поэтому хороший тест сначала использует прямоугольник, затем проверяет нулевые измерения: форма 0 на 3 превращается в 3 на 0. Это допустимые массивы без элементов, но их формы различаются.

Для соседей клетки отдельно проверяют каждое направление. Слева сосед существует только при `column>0`, справа — при `column+1<columns`. На углу соседей меньше, чем внутри. Порядок «сначала граница, потом чтение» обеспечивает безопасность. Если проверяется строгая вершина, равный сосед запрещает вершину; диагональ участвует только при явном требовании.

Не путайте прямоугольный `int[,]` с массивом массивов `int[][]`. Во втором случае каждая строка — отдельный объект и может иметь свою длину. Выбор структуры должен отражать данные. Для регулярной таблицы в этом модуле используется прямоугольная форма; знания о ссылках достаточно, чтобы понимать, почему копирование внешнего массива не копирует автоматически внутренние строки.

## 7. Проверка и самостоятельные вопросы

Разделяйте корректность и стоимость. Линейный обход требует порядка `n` шагов, бинарный поиск — порядка логарифма длины, обработка всей матрицы — произведения размеров. Два последовательных линейных прохода остаются `O(n)`. Два вложенных прохода по одному массиву могут давать `O(n²)`. Дополнительный массив — тоже часть оценки памяти.

При ошибке сначала уменьшите вход: пустой массив, один элемент, два равных элемента, два разных. Затем проверьте состояние до записи и после неё. В отладчике следите одновременно за индексами и значениями, а не только за итоговым выводом. Для проверки копии измените результат и снова прочитайте источник. Для проверки порядка используйте массив, который отличается от своего обращения.

Ответьте до просмотра последнего раздела: почему индекс `Length` недопустим? Почему два разворота не доказывают правильность Reverse? Чем различаются отбор и сортировка? Почему нижняя граница может равняться длине? Какой тест лучше различает прямоугольную и квадратную реализацию транспонирования? Почему сумму строки нужно сбрасывать перед следующей строкой?

## 8. Ответы самопроверки

**Индекс Length.** При длине `n` существует ровно `n` позиций, отсчитанных от нуля. Последний индекс равен `n-1`. Позиция `n` полезна как граница интервала и место вставки в будущий список, но не как адрес существующего элемента. Пустой массив особенно хорошо показывает разницу: длина ноль не создаёт элемент с индексом ноль.

**Два разворота.** Свойство «повторная операция возвращает исходник» необходимо, но недостаточно. Метод, который ничего не делает, тоже проходит его. Нужен хотя бы один заранее рассчитанный асимметричный пример, например `[1,2,3]` с ожидаемым `[3,2,1]`. Дополнительно проверяются пустота, чётная длина и дубликаты.

**Отбор и сортировка.** Отбор решает, какие элементы оставить, обычно сохраняя порядок оставшихся. Сортировка переставляет элементы по отношению порядка, сохраняя их число. Если после отбора `[4,1,4]` получилось `[1,4,4]`, множество чисел верно, но требование исходного порядка нарушено.

**Нижняя граница.** Если все значения меньше цели, первой подходящей ячейки нет, но место вставки находится после всех существующих элементов. Число `Length` представляет эту позицию. Перед проверкой равенства нужно убедиться, что позиция меньше длины. Сам бинарный поиск при этом может быть совершенно корректным.

**Транспонирование.** Прямоугольник 2 на 3 обнаруживает неверно выбранные размеры результата. Проверяйте не только общую длину шесть, но отдельно размеры 3 и 2 и значения вне диагонали. Нулевые измерения дополняют проверку формы. Двойное транспонирование полезно, но само по себе может пропустить реализацию, вообще ничего не меняющую.

**Суммы строк.** Аккумулятор строки описывает только текущую строку. Если перенести его инициализацию за внешний цикл, суммы станут префиксными: вторая строка будет включать первую, третья — обе предыдущие. Полностью отрицательная матрица и строка с маленькой суммой после большой помогают заметить такой дефект.
