# Первая программа, типы и выражения

## 1. Маршрут первой программы

Предварительные знания программирования не требуются. Нужно уметь открыть папку, сохранить файл и выполнить команду в терминале. Результат урока — небольшая программа, для которой вы можете объяснить тип каждой переменной, порядок вычислений и выбранный способ проверки. Сначала запустите [пример](examples/Program.cs), затем прочитайте разделы о числах, решите несколько [задач](TASKS.md) и только после собственной попытки сверяйтесь с [решениями](SOLUTIONS.md). Для занятий в Visual Studio используйте общую [инструкцию](../../docs/VISUAL_STUDIO.md); требования к SDK перечислены в [настройке среды](../../docs/ENVIRONMENT_SETUP.md).

В курсе используется .NET 10. SDK содержит компилятор и команды сборки; среда выполнения запускает собранную программу. Файл `.cs` хранит исходный текст. Файл `.csproj` описывает проект: какие исходники собирать и какую платформу использовать. Решение объединяет несколько проектов, но не превращает их в один бесконечный исходный файл. Команда `dotnet build` проверяет возможность сборки, а `dotnet run --project ...` собирает и запускает выбранный проект.

Для самого короткого консольного приложения достаточно инструкции:

```csharp
Console.WriteLine("Начало работы");
```

Точка с запятой завершает инструкцию. Кавычки задают строковый литерал, а `WriteLine` выводит его с переводом строки. Регистр имён значим: `Console` и `console` — разные записи. В примерах можно встретить `using Course;` и `Check.Equal(...)`: это предоставленная инфраструктура проверок. Классы `Task01`, методы `Run` и оболочки с параметрами в уроках 01–03 также подготовлены преподавателем. Пока вы пишете тело вычисления, читая аргументы как уже известные входные данные. Самостоятельно проектировать методы начнём в уроке 04, классы — в уроке 08.

## 2. Переменная хранит значение определённого типа

Объявление `int count = 12;` создаёт переменную `count` типа `int` и присваивает ей начальное значение. Тип ограничивает возможные данные и доступные операции. Количество предметов обычно целое; название товара — текст; результат сравнения — логическое значение. Выбор типа делается по смыслу данных и необходимому диапазону, а не по желаемому виду строки на экране.

| Тип | Типичный смысл | Существенная граница |
| --- | --- | --- |
| `int` | Счётчик, целое количество | От −2147483648 до 2147483647 |
| `long` | Большое целое произведение или сумма | Более широкий, но также конечный диапазон |
| `double` | Измерение, вещественное приближение | Двоичная арифметика с погрешностью |
| `decimal` | Десятичная сумма по заданным правилам | Литерал `19.90m`, точность конечна |
| `bool` | Ответ да/нет | Значения `true` и `false` |
| `char` | Одна кодовая единица UTF-16 | Один `char` не всегда целый знак Unicode |
| `string` | Текст | Неизменяемое строковое значение |

Присваивание `count = count + 1;` не является уравнением. Сначала читается старое значение справа, вычисляется сумма, затем новое значение записывается слева. Имя лучше выбирать по предметному смыслу: `seconds`, `quantity`, `unitPrice`. Имена `a`, `b` удобны в короткой формуле, но затрудняют чтение расчёта чека. Комментарий должен пояснять причину решения, а не повторять очевидное: «используем long, потому что произведение может превысить int» полезнее, чем «умножаем ширину на высоту».

## 3. Выражение вычисляется до присваивания

Тип правой части определяется её операндами. Переменная назначения не исправляет уже выполненную операцию:

```csharp
int total = 7;
int count = 2;
double lost = total / count;
double kept = (double)total / count;
```

В `lost` записывается `3.0`, потому что сначала произошло целочисленное деление. В `kept` один операнд заранее стал `double`, поэтому получаем `3.5`. Запись `(double)(total / count)` снова преобразует уже усечённое целое и дробь не возвращает. При делении целых отрицательное частное округляется к нулю: `-7 / 3` равно `-2`. Остаток согласован с тождеством `a == (a / b) * b + a % b`; поэтому `-7 % 3` равно `-1`.

Приоритет операций помогает читать формулу: умножение и деление выполняются раньше сложения и вычитания. Скобки задают нужную группировку и позволяют обозначить смысл. `price * (1m - percent / 100m)` выражает оставшуюся после скидки долю. Если есть сомнение, вначале вычислите промежуточные величины отдельно, проверьте их единицы измерения и только затем объединяйте формулу.

Например, метры, разделённые на секунды, дают м/с. Для км/ч нужен множитель `3.6`: за час 3600 секунд, в километре 1000 метров. Нельзя решить такую задачу одним угадыванием «нужно где-то умножить на 1000». Проверка размерности часто обнаруживает ошибку до первого запуска программы.

## 4. Трассировка вместо угадывания

Рассмотрим независимый фрагмент:

```csharp
int x = 3;
int y = x + 4;
x = y * 2;
y = x - y;
Console.WriteLine($"{x}:{y}");
```

| После инструкции | x | y |
| --- | --- | --- |
| Объявление x | 3 | ещё не объявлена |
| Объявление y | 3 | 7 |
| Присваивание x | 14 | 7 |
| Присваивание y | 14 | 7 |

Итог — `14:7`. Последняя строка арифметики читает новое `x`, а не первоначальную тройку. Таблица пригодна и в отладчике: остановитесь перед интересующей строкой, запишите ожидаемое состояние, выполните один шаг и сравните наблюдение с прогнозом. Если итог неверен, ищите первое место расхождения, а не меняйте несколько формул одновременно.

Знак `$` перед строкой включает интерполяцию: выражение в `{...}` подставляется в текст. Интерполяция удобна для отчёта, но не делает арифметику точнее. Вычисления нужно проверить до оформления результата. Символы формата тоже являются частью контракта: если требуется `H:M:S`, лишний пробел или ведущий ноль может означать неверный результат задачи даже при правильных числах.

## 5. Decimal, double и правила округления

`double` удобен для измерений, где заранее определена допустимая погрешность. Многие десятичные дроби не имеют точного конечного двоичного представления. Поэтому результат `0.1 + 0.2` может отличаться от хранимого `0.3` на очень малую величину. Это не случайность конкретного компьютера и не повод округлять каждое промежуточное действие. Для задачи с абсолютным допуском сравнивают `Math.Abs(actual - expected) <= tolerance`. Сам допуск должен следовать из условия; универсального подходящего всем задачам числа нет.

Для денежных расчётов с десятичными входами в этом курсе используется `decimal`. Суффикс `m` отличает десятичный литерал от `double`: `0.10m`. Операции с decimal также имеют ограниченную точность; например, треть невозможно записать конечным количеством десятичных знаков. Не следует обещать, что этот тип автоматически решает все вопросы точности и финансовых правил.

Округление — отдельное решение. При `Math.Round(amount, 2, MidpointRounding.AwayFromZero)` точная середина уходит от нуля. Без явного режима стандартное округление выбирает ближайшее чётное на середине. Число `2.345m` различает эти политики, а `1.234m` — нет. Покупка целых банок краски имеет иной смысл: применяется `Math.Ceiling`, чтобы материала хватило. Обычное усечение дроби оставило бы непокрытую площадь. Сначала назовите предметное правило, затем выбирайте библиотечный вызов.

## 6. Var, расширение и переполнение

`var` не означает, что тип переменной будет меняться. В `var value = 7;` компилятор один раз выводит `int`. Затем `value = 1.5;` недопустимо. Если требуется дробное значение, объявляйте `double value = 7;` либо используйте изначально дробный инициализатор. Полезность `var` зависит от ясности кода: очевидный инициализатор позволяет убрать повторение типа, но сам тип всё равно существует.

Присваивание произведения в `long` не расширяет операцию автоматически. В `long area = width * height;` два int умножаются как int. Для большой площади пишут `(long)width * height`. Приведение после скобок снова опоздает. Алгебраическое преобразование формулы тоже требует учёта промежуточных диапазонов: равенство математических выражений ещё не доказывает одинаковое поведение машинных операций при выходе за границы.

`checked(a + b)` требует сообщить о целочисленном переполнении через `OverflowException`; `unchecked(a + b)` явно задаёт оборачивание. Checked не подбирает больший тип. В задачах событие проверяет готовый `Check.Throws`, поэтому собственные обработчики исключений пока не нужны. Checked действует на операции, записанные внутри соответствующего выражения или блока; его нельзя считать глобальным переключателем для внутренностей вызванного метода. Детали и границы механизма изложены в [справке Microsoft](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/checked-and-unchecked).

## 7. Проверка программы по наблюдаемому результату

Успешная сборка подтверждает согласованность исходного текста с правилами языка. Она не доказывает, что вы выбрали нужную формулу. Для вычисления полезны обычный пример, вырожденный вход, обе границы диапазона и случай, на котором вероятная ошибка проявится. У среднего арифметического нужен нечётный числитель, у произведения — результат больше int, у округления — точная середина. Десять однотипных маленьких примеров слабее одного различающего.

`Check.Equal(expected, actual)` сравнивает точный результат; ожидаемое значение стоит первым. `Check.Near` применяют к конечным вещественным значениям с указанным допуском. Проверка должна получать фактический результат метода, а не сравнивать два заранее записанных одинаковых литерала. Для ошибки компиляции не существует корректного «запуска исходной версии»: сначала объясните диагностику, затем исполняйте исправленный аналог. Для ошибочного, но компилируемого фрагмента полезно выполнить и его, и исправление.

После каждой задачи устно назовите входы, выход, область допустимости и один случай отказа или ограничения. Не добавляйте произвольную обработку входов, которые условие явно исключает: сначала соблюдайте заданный контракт. Позже вы научитесь проектировать такие контракты самостоятельно. Здесь точность постановки важнее количества набранных строк.

При ошибке сборки начните с первой осмысленной диагностики и указанного места в исходнике. Одна пропущенная кавычка способна породить несколько последующих сообщений, которые исчезнут вместе с первопричиной. Сохраняйте файл перед повторным запуском и проверяйте, что выбран нужный проект: иначе можно наблюдать исправную, но совсем другую программу. После исправления снова выполните тот вход, на котором возникла проблема.

## 8. Самопроверка и подробные ответы

Сначала ответьте самостоятельно: почему присваивание в double не спасает целое деление? Когда нужен суффикс m? Что меняет checked? Почему тест `8/2` недостаточен для среднего? Что именно выводит var? Чем отличаются округление цены и округление количества упаковок?

Ответ 1. Правая часть вычисляется до присваивания. При двух int дробная часть теряется в делении; нужен вещественный операнд до операции. Ответ 2. Суффикс m задаёт decimal-литерал и позволяет согласовать десятичную формулу без смешивания с double. Ответ 3. Checked меняет реакцию на определённые переполнения, а не диапазон типа; при выходе за int возникает исключение. Ответ 4. При точном делении правильная и ошибочная версии совпадут. На `7/2` они различаются как 3.5 и 3.0.

Ответ 5. Var выводит статический тип по инициализатору один раз. Последующие значения должны быть совместимы с ним. Ответ 6. Цена округляется по заданному денежному правилу до нужного числа знаков. Количество целых упаковок для покрытия потребности округляется вверх; усечение или округление к ближайшему может дать недостаток. Содержательно завершённый ответ должен назвать и оператор или API, и причину его выбора.
