## 04-01. Ограничение числа диапазоном

Уровень 1 · Реализация · Навык: Контракт чистого метода с тремя параметрами

Напишите `int Clamp(int value, int minimum, int maximum)`.
Допустимы любые int при minimum<=maximum. Верните ближайшее к value число из закрытого
диапазона [minimum,maximum]. Для value внутри диапазона верните его без изменения.
Вне предусловия minimum<=maximum метод не вызывается. Math.Clamp использовать нельзя.
Метод не должен читать или печатать данные.

**Пример и ожидаемое поведение**

`Clamp(-2,0,10)` → `0`; `Clamp(4,0,10)` → `4`; `Clamp(12,0,10)` → `10`.

<a id="04-02"></a>
## 04-02. Два исхода целого деления через out

Уровень 1 · Реализация · Навык: Обязательная инициализация out и отдельный признак успеха

Реализуйте `bool TryDivide(int dividend, int divisor, out int quotient)` для любых int.
При делении на ноль и при единственном переполнении int.MinValue / -1 верните false,
quotient обязан быть 0. Иначе верните true и частное, округлённое к нулю.
Не используйте исключение как обычный способ ветвления. Ввод/вывод не нужен.

**Пример и ожидаемое поведение**

`TryDivide(7,2,out q)` → true,q=3; `(7,0)` → false,q=0.

<a id="04-03"></a>
## 04-03. Обмен копиями и обмен переменными

Уровень 1 · Чтение кода · Навык: Передача значимого типа по значению и через ref

Дан метод:
```csharp
public static void Exchange(int a, int b)
{
    int temporary = a;
    a = b;
    b = temporary;
}
```
Во внешнем коде `int x=2; int y=9; Exchange(x,y);` — какими станут x,y?
Воспроизведите исходник и реализуйте `void Swap(ref int a, ref int b)`, реально меняющий
две переменные. Допустимы любые int; передача одной и той же переменной дважды должна
оставлять её значение прежним. Нельзя использовать арифметический обмен с риском переполнения.

**Пример и ожидаемое поведение**

После Exchange: x=2,y=9; после Swap(ref x,ref y): x=9,y=2.

## 04-04. Именованные и необязательные аргументы

Уровень 1 · Реализация · Навык: Отличие порядка параметров от именования аргументов в вызове

Объявите `decimal Total(decimal unitPrice, int quantity = 1, decimal fee = 0m)`.
unitPrice и fee от 0 до 1 000 000, quantity от 0 до 1000; вне диапазонов вызовов нет.
Стоимость равна unitPrice*quantity + fee, сбор добавляется один раз даже при нулевом количестве.
Покажите вызовы с одним аргументом, с двумя, с именованным fee без quantity и с именованными
аргументами в ином порядке. Для каждого проверьте результат.

**Пример и ожидаемое поведение**

`Total(10m)` → `10m`; `Total(10m,fee:3m)` → `13m`; `Total(fee:3m,quantity:2,unitPrice:10m)` → `23m`.

## 04-05. Как выбирается перегрузка

Уровень 1 · Чтение кода · Навык: Выбор метода по статическому типу аргумента

Даны две перегрузки:
```csharp
public static string Describe(int value) { return $"int:{value}"; }
public static string Describe(double value)
{
    return "double:" + value.ToString(System.Globalization.CultureInfo.InvariantCulture);
}
```
Предскажите результаты вызовов Describe(7), Describe(7.0), а также
`var x=7; Describe(x);` и `double y=7; Describe(y);`.
Воспроизведите обе перегрузки. int допустим любой, double — конечный по модулю до 1 000 000;
вне этих условий вызовов нет.

**Пример и ожидаемое поведение**

`Describe(7)` → `"int:7"`; `Describe(7.0)` → `"double:7"`.

## 04-06. Возврат на каждом пути

public static bool IsEven(int value)

Допустимы любые int; отрицательные чётные также дают true.
Предпочтительна версия без локальной переменной и без else, возвращающая bool-выражение.

**Пример и ожидаемое поведение**

`IsEven(-4)` → true; `IsEven(-3)` → false; `IsEven(0)` → true.

## 04-07. Чек без смешивания расчёта и печати

Уровень 2 · Рефакторинг · Навык: Декомпозиция предметных правил и форматирования

Дан расчёт в консольной программе:
```csharp
decimal subtotal = price * quantity;
decimal rate = quantity >= 10 ? 0.10m : 0m;
decimal discount = subtotal * rate;
Console.WriteLine($"{subtotal} / {discount} / {subtotal - discount}");
```
Выделите `decimal Subtotal(decimal price,int quantity)`, `decimal DiscountRate(int quantity)`
и `string Receipt(decimal price,int quantity)`. price от 0 до 100000 с не более чем двумя знаками,
quantity от 0 до 1000. Вне диапазонов вызовов нет. Receipt возвращает ровно
`subtotal=0.00;discount=0.00;total=0.00` с фактическими числами, точкой и без пробелов;
сначала округлите рассчитанную скидку до двух знаков AwayFromZero, затем вычтите именно
уже округлённую скидку из subtotal. Таким образом показанный итог согласован с показанными
составляющими чека. В методы не добавляйте Console.

**Пример и ожидаемое поведение**

`Receipt(10m,10)` → `"subtotal=100.00;discount=10.00;total=90.00"`.

## 04-10. Трасса возврата из рекурсии

Уровень 2 · Чтение кода · Навык: Вычисление выражения вокруг незавершённого вызова

Воспроизведите точный метод:
```csharp
public static string Trace(int n)
{
    if (n == 0) return "0";
    return $"{n}[{Trace(n - 1)}]{n}";
}
```
n от 0 до 5; вне диапазона вызовов нет.
Без запуска назовите Trace(2), затем покажите порядок вызовов и порядок получения готовых строк.
Подтвердите ответ выполнением для 0,1,2,3. Не заменяйте результат одними числами на прямом ходе.

**Пример и ожидаемое поведение**

`Trace(2)` → `"2[1[0]1]2"`.

## 04-11. Проверять bool и out вместе

Уровень 3 · Проектирование тестов · Навык: Проверка полного контракта Try-метода на отказе

Требуется `bool TryPositive(string? text, out int value)`.
Успех только для корректного int >0; иначе false и обязательно value=0.
null, пустая строка, неверный формат и переполнение считаются обычным отказом, длина до 100.
Напишите правильный метод и исполняемые тесты, отличающие его от:
```csharp
public static bool Wrong(string? text, out int value)
{
    return int.TryParse(text, out value) && value > 0;
}
```
Объясните, почему одной проверки bool недостаточно.

**Пример и ожидаемое поведение**

`TryPositive("-5",out x)` → false,x=0; Wrong → false,x=-5.

## 04-13. Вывод через предоставленный приёмник

Уровень 3 · Реализация · Навык: Явная зависимость вместо жёсткого Console

Напишите `void PrintRange(TextWriter output,int from,int to)`.
output не null, from и to от -100 до 100. При from<=to запишите каждое целое число
включительно отдельной строкой через output.WriteLine; при from>to не пишите ничего.
Источник вывода предоставляет каркас, устройство TextWriter пока достаточно понимать как
объект с WriteLine. Не используйте Console и не закрывайте output.
Перевод строки определяется output.NewLine; проверка должна учитывать именно его.

**Пример и ожидаемое поведение**

При NewLine=`\n`, `PrintRange(output,-1,1)` создаёт `"-1\n0\n1\n"`.

## 04-14. Часы: совместное изменение двух ref-параметров

Уровень 3 · Реализация · Навык: Атомарный отказ и нормализация циклического состояния

Реализуйте `bool TryAdvanceClock(ref int hours,ref int minutes,int deltaMinutes)`.
Для успеха нужны hours в 0..23, minutes в 0..59 и deltaMinutes в 0..1440 включительно.
При успехе прибавьте deltaMinutes с переходом через полночь и верните true.
При любом недопустимом int верните false, обе переменные должны сохранить исходные значения.
Ноль минут добавлять допустимо; 1440 минут возвращают то же время.
Два ref по предусловию указывают на разные переменные. DateTime и TimeSpan не используйте.

**Пример и ожидаемое поведение**

hours=23,minutes=50,deltaMinutes=20 → true,hours=0,minutes=10; +1440 → исходное время.

## 04-15. Проверка номера с контрольной цифрой

Уровень 3 · Прикладная задача · Навык: Декомпозиция проверки формата, расчёта и диагноза

Создайте независимые методы `bool IsFourDigits(int code)`, `int ExpectedDigit(int prefix)`
и `string InspectCode(int code)`. Любой int допустим для первого и третьего методов.
prefix для ExpectedDigit от 100 до 999; вне этого предусловия его не вызывают.
У четырёхзначного десятичного номера abcD (a≠0) контрольная цифра должна быть
D=(3*a+2*b+c)%10. InspectCode возвращает `range` для числа вне 1000..9999,
`valid` для правильной контрольной цифры, иначе `checksum`.
InspectCode обязан пользоваться двумя помощниками. Строковое преобразование числа не требуется.

**Пример и ожидаемое поведение**

`InspectCode(1230)` → `"valid"`; `InspectCode(1234)` → `"checksum"`; `InspectCode(999)` → `"range"`.
