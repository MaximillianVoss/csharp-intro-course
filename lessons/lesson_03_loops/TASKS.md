## 03-06. Итерация do/while для нулевого старта

Уровень 2 · Чтение кода · Навык: Отличие проверки до тела от проверки после тела

Воспроизведите метод:
```csharp
public static int Steps(int start)
{
    int x = start;
    int steps = 0;
    do
    {
        x /= 2;
        steps++;
    } while (x > 0);
    return steps;
}
```
start от 0 до 1 000 000. Предскажите Steps(0), Steps(1), Steps(8), запишите значения x после
каждого тела для старта 8. Вне диапазона вызовов нет. Не заменяйте do/while на другой цикл.

**Пример и ожидаемое поведение**

`Steps(0)` → `1`; `Steps(8)` → `4` при x: 4,2,1,0.

## 03-07. Простой квадрат и неверная граница

Уровень 2 · Поиск ошибки · Навык: Полнота перебора делителей и безопасная граница sqrt(n)

Исправьте метод для любого int n от 0 до int.MaxValue:
```csharp
public static bool Broken(int n)
{
    if (n < 2) return false;
    for (int d = 2; d * d < n; d++)
        if (n % d == 0) return false;
    return true;
}
```
Требуемый метод `bool IsPrime(int n)` возвращает true ровно для простых чисел.
Укажите две проблемы границы d*d&lt;n. У исправленного метода не должно быть переполнения
в проверке цикла. Отдельно выполните исходник на 49; большие опасные n в исходник передавать не требуется.

**Пример и ожидаемое поведение**

Исходный `Broken(49)` → true (ошибка); `IsPrime(49)` → false; `IsPrime(2)` → true.

## 03-08. Одно место чтения строки

Уровень 2 · Рефакторинг · Навык: Цикл чтения до EOF без дублирования обновления

Каркас предоставляет TextReader reader — источник с методом ReadLine, возвращающим строку или null;
устройство объектов пока изучать не требуется. Дан рабочий метод:
```csharp
public static long Original(TextReader reader)
{
    long sum = 0;
    string? line = reader.ReadLine();
    while (line is not null)
    {
        if (int.TryParse(line, out int value)) sum += value;
        line = reader.ReadLine();
    }
    return sum;
}
```
Напишите эквивалентный `long SumLines(TextReader reader)` с единственным вызовом ReadLine в тексте метода,
using while(true) и break. reader не null; не более 1000 строк до 100 символов;
успешно разобранные int могут иметь любое значение. Неверные строки пропускаются,
пустой поток даёт 0. Источник не закрывайте: он принадлежит вызывающему коду.

**Пример и ожидаемое поведение**

Поток `3\nbad\n-2\n` → `1L`; пустой поток → `0L`.

Уровень 2 · Реализация · Навык: Итерационная модель с ограничением числа шагов

Реализуйте `int Years(decimal initial, decimal target, int maxYears)`.
initial,target от 0 до 1 000 000; maxYears от 0 до 30. В начале года 0 на счёте initial.

## 03-11. Тесты границы повторного вычитания

Уровень 3 · Проектирование тестов · Навык: Различающий случай равенства в условии цикла

Нужен `int Quotient(int dividend, int divisor)` — целая часть деления неотрицательного
dividend (0..10000) на divisor (1..1000) через повторное вычитание, без `/` и `%` в методе.
Остаток не возвращается. Вне диапазонов вызовов нет. Напишите тесты, выявляющие ошибку:
```csharp
public static int Wrong(int dividend, int divisor)
{
    int count = 0;
    while (dividend > divisor)
    {
        dividend -= divisor;
        count++;
    }
    return count;
}
```
Реализуйте правильный метод и исполните набор для обоих вариантов хотя бы на одном различающем входе.

**Пример и ожидаемое поведение**

`Quotient(12,3)` → `4`; исходный Wrong даёт `3`; `Quotient(2,3)` → `0`.

## 03-15. Ограниченные попытки и ранний выход

Уровень 3 · Прикладная задача · Навык: Состояние ограниченного протокола и сохранение непрочитанного хвоста

Реализуйте учебный протокол `string TryCode(TextReader reader, int limit)`.
reader не null; limit от 1 до 10. На каждой попытке читается одна строка (до 100 символов).
Только точный текст `0420` считается совпадением: верните `ok:N`, N — номер попытки с 1.
Если до совпадения встретился EOF, верните `eof`. Если limit непустых или пустых строк прочитаны
без совпадения, верните `locked`. Пустая строка и любой неверный формат расходуют попытку.
После совпадения или лимита больше ничего не читайте, reader не закрывайте.
Это упражнение на цикл и строковое равенство, не схема хранения настоящих секретов.

**Пример и ожидаемое поведение**

Поток `bad\n0420\nnext\n`, limit=3 → `"ok:2"`, строка next остаётся непрочитанной.
