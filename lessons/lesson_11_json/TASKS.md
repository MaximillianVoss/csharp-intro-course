## 11-01. Карточка в JSON

Уровень 1 · Реализация · Навык: Сериализация свойств DTO

Реализуйте string Serialize(Card card), где Card содержит свойства string Name и int Count. Имя непустое после Trim, Count >= 0; само имя сохраняйте без обрезки. null card вызывает ArgumentNullException, неверные свойства — ArgumentException. Верните компактный JSON с именами Name и Count. Порядок полей несущественен; управляющие символы должны корректно экранироваться.

**Пример и ожидаемое поведение**

Card { Name="чай", Count=2 } → объект JSON с Name="чай", Count=2.

<a id="11-02"></a>
## 11-02. Чтение показания

Уровень 1 · Реализация · Навык: Десериализация и последующая доменная проверка

Реализуйте Reading Read(string json). Модель Reading: decimal Value, string? Unit. Принимается JSON-объект со свойствами Value и Unit (регистр значим); допустимы Value от -1000 до 1000 включительно и Unit "C" или "F". Отсутствующее Value имеет значение 0 по правилам DTO. null JSON-корень и неверные доменные значения вызывают JsonException, неверный синтаксис/тип тоже JsonException. null аргумент — ArgumentNullException. Лишние поля игнорируются.

**Пример и ожидаемое поведение**

{"Value":12.5,"Unit":"C"} → Reading(12.5,"C"); {"Unit":"K"} → JsonException.

<a id="11-03"></a>
## 11-03. Что действительно прочитано

Уровень 1 · Чтение кода · Навык: Регистр свойств и исключённые поля

Укажите два числа, которые выведет код, и объясните оба результата. Затем реализуйте (int Limit, int Counter) Observe(string json), выполняющий точно такое же чтение и возвращающий значения. JSON null-корень отклоняйте JsonException; null аргумент — ArgumentNullException. Прочие ошибки оставьте сериализатору.
```csharp
var s = JsonSerializer.Deserialize<Settings>("{\"limit\":2,\"Counter\":7}")!;
Console.WriteLine($"{s.Limit},{s.Counter}");

public sealed class Settings
{
    public int Limit { get; set; } = 9;
    public int Counter = 4;
}
```
Не включайте IncludeFields и нечувствительность к регистру.

**Пример и ожидаемое поведение**

Для приведённого JSON верните пару чисел, соответствующую фактическому выводу программы.

<a id="11-04"></a>
## 11-04. Исправление времени жизни JsonElement

Уровень 1 · Поиск ошибки · Навык: JsonElement зависит от владеющего JsonDocument

Исправьте JsonElement ReadDetached(string json), сохранив сигнатуру и принимая любой корректный JSON-корень. После возврата вызывающий должен безопасно читать все вложенные значения. Исходный код:
```csharp
static JsonElement ReadDetached(string json)
{
    using var document = JsonDocument.Parse(json);
    return document.RootElement;
}
var element = ReadDetached("{\"Name\":\"Ada\"}");
Console.WriteLine(element.GetProperty("Name").GetString());
```
Документ необходимо освобождать внутри метода; запретите утечку вместо удаления using. null аргумент — ArgumentNullException; неверный JSON — JsonException. JSON null допустим и возвращается как элемент соответствующего ValueKind. Объясните причину ошибки при обращении к исходному результату.

**Пример и ожидаемое поведение**

ReadDetached для {"Name":"Ada"} → после возврата доступен Name="Ada"; для [1,2] → доступны оба элемента.

<a id="11-05"></a>
## 11-05. Нет поля и поле null

Уровень 1 · Реализация · Навык: Трёхсостояние JSON-свойства

Реализуйте string Label(string json). Корень обязан быть объектом. Если свойства label нет, верните "нет"; если оно JSON null — "пусто"; если строка — её точное значение, включая пустую строку. Любой иной тип label, неверный корень или синтаксис — JsonException. null аргумент — ArgumentNullException. Остальные поля игнорируются. JsonDocument освобождайте до возврата.

**Пример и ожидаемое поведение**

{} → "нет"; {"label":null} → "пусто"; {"label":""} → "".

<a id="11-06"></a>
## 11-06. Настройки в собственном файле

Уровень 2 · Прикладная задача · Навык: JSON и контролируемое файловое хранение

Создайте Settings с int Volume (0..100). Реализуйте void Save(string path, Settings settings) и Settings Load(string path). Save пишет JSON с отступами; неверная громкость — ArgumentException, null объект — ArgumentNullException. Load для отсутствующего файла при существующем каталоге возвращает новый Settings с Volume=50; для существующего пустого/испорченного файла, null-корня или неверной громкости — JsonException. Остальные файловые ошибки, включая отсутствие каталога, распространяются. null/пустой путь — ArgumentException. Тесты работают только в уникальном временном каталоге и удаляют его в finally.

**Пример и ожидаемое поведение**

Отсутствующий settings.json → Volume=50; Save(...,Volume=0), Load(...) → 0.

<a id="11-07"></a>
## 11-07. Сумма вложенного заказа

Уровень 2 · Реализация · Навык: Валидация вложенных коллекций DTO

Реализуйте decimal Total(string json). Корень — объект Order со свойством Lines: массив строк {Quantity:int, Price:decimal}. Lines обязателен и не null; допустим пустой массив. Quantity от 1 до 1000, Price от 0 до 1000000 включительно. null-строка массива и неверное значение — JsonException. Возвращается сумма Quantity*Price, без округления. Синтаксические ошибки/неверные JSON-типы — JsonException, null аргумент — ArgumentNullException. Переполнение суммы — OverflowException.

**Пример и ожидаемое поведение**

{"Lines":[{"Quantity":2,"Price":1.25},{"Quantity":1,"Price":0}]} → 2.50.

<a id="11-08"></a>
## 11-08. Координаты без DTO

Уровень 2 · Реализация · Навык: Чтение динамической структуры через JsonDocument

Реализуйте (double Lat, double Lon) ReadPoint(string json). JSON — объект с обязательными числовыми lat и lon, диапазоны [-90,90] и [-180,180]. Строковые числа не принимаются. Нефинитное или выходящее за диапазон значение, отсутствие свойства, неверный корень — JsonException. Лишние поля игнорируются. null аргумент — ArgumentNullException. Не возвращайте JsonElement из освобождённого документа.

**Пример и ожидаемое поведение**

{"lat":55.75,"lon":37.62} → (55.75,37.62); {"lat":"0","lon":0} → JsonException.

<a id="11-09"></a>
## 11-09. Убираем склейку JSON

Уровень 2 · Рефакторинг · Навык: Корректное экранирование при потоковой записи JSON

Перепишите string BuildMessage(string text), сохранив контракт {"text":строка}. Исходник:
```csharp
static string BuildMessage(string text) => "{\"text\":\"" + text + "\"}";
```
Допустимы строки с корректной UTF-16-последовательностью Unicode, включая пустую строку, кавычки, обратную косую черту, перенос, кириллицу и emoji. Старший суррогат должен непосредственно сопровождаться младшим, одиночный младший суррогат запрещён. Непарный суррогат — ArgumentException до записи; null — ArgumentNullException. Результат должен быть корректным JSON и после чтения возвращать исходный текст без нормализации. Конкретная форма Unicode-экранирования несущественна. Запишите объект через Utf8JsonWriter в MemoryStream; не создавайте DTO и не пишите собственный Replace для экранирования.

**Пример и ожидаемое поведение**

Текст a"b и перенос строки → JSON, из которого GetProperty("text").GetString() возвращает ровно исходную строку.

## 11-10. Тесты сохранения порядка

Уровень 2 · Проектирование тестов · Навык: Проверка round trip по содержимому

Напишите int[] RoundTrip(int[] values): сериализация и обратное чтение нового массива без изменения порядка, повторов и исходного массива. null аргумент — ArgumentNullException. Составьте исполняемые тесты для пустого массива, отрицательных значений, повторов и неотсортированного ввода. Докажите тестом, что неверная реализация, сортирующая восстановленный массив, обнаруживается. Сравнения ссылок недостаточно.

**Пример и ожидаемое поведение**

[3,-1,3,0] → [3,-1,3,0]; SortedRoundTrip для этого ввода должен не пройти критерий порядка.

## 11-11. Миграция версии настроек

Уровень 3 · Реализация · Навык: Явная совместимость формата

Реализуйте Config Read(string json), возвращающий Config(string Name,int Retries). Формат v1: {"version":1,"label":"..."}, Retries=3. Формат v2: {"version":2,"name":"...","retries":целое 0..5}. Указанные поля обязательны, имена непустые после Trim; сохраняйте исходное имя. Лишние поля разрешены. Отсутствие/неверный тип/version вне 1..2/null-корень — JsonException. null аргумент — ArgumentNullException. Не пытайтесь угадать версию по наличию label.

**Пример и ожидаемое поведение**

{"version":1,"label":"demo"} → Config("demo",3); версия 3 → JsonException.

<a id="11-12"></a>
## 11-12. Построчный импорт NDJSON

Уровень 3 · Реализация · Навык: Локализация ошибок независимых записей

Реализуйте Report Import(TextReader reader): каждая непустая/непробельная строка содержит самостоятельный JSON-объект {"Id":положительный int}. Report содержит List<int> Ids и List<int> ErrorLines. Пустые строки пропускайте, но учитывайте при нумерации с 1. Некорректный синтаксис, неверный Id, отсутствие Id и JSON null записывают номер в ErrorLines, импорт продолжается. Повторные Id разрешены. EOF завершает импорт. null reader — ArgumentNullException; reader не закрывайте; другие ошибки чтения распространяются.

**Пример и ожидаемое поведение**

Строки: {"Id":2}, пустая, {bad}, {"Id":3} → Ids=[2,3], ErrorLines=[3].

<a id="11-13"></a>
## 11-13. Статус как строка

Уровень 3 · Реализация · Навык: Точный строковый контракт перечисления

Объявите enum Status { Pending, Done }. Реализуйте Status Read(string json) и string Write(Status status). Внешний формат — JSON-строка, декодированное значение которой равно ровно "Pending" либо "Done" по StringComparison.OrdinalIgnoreCase. Пробелы внутри строки не обрезайте; составные имена, в том числе "Pending, Done" и "Done, Done", запрещены. JSON-числа, числовые строки, неизвестные имена, null и другие типы — JsonException. Внешние пробелы JSON вокруг строкового токена допустимы. Write выдаёт каноническое имя с заглавной буквы; неопределённое значение enum вызывает ArgumentOutOfRangeException. null аргумент Read — ArgumentNullException. Для записи используйте строковый конвертер без поддержки целых значений; при чтении отдельно проверьте точные имена.

**Пример и ожидаемое поведение**

JSON "done" → Done; JSON " done " и "Pending, Done" → JsonException; Write(Pending) → JSON "Pending".

<a id="11-14"></a>
## 11-14. Частичное обновление профиля

Уровень 3 · Реализация · Навык: Отличие отсутствующего поля от сброса

Реализуйте Profile Patch(Profile original,string json), где immutable Profile — record(string Name,string? Bio). Исходное Name непустое. JSON-объект может содержать только name и bio, каждый не более одного раза. Отсутствующее поле сохраняется; name обязано быть непустой строкой; bio — строка или null (сброс). Неизвестное/повторное поле, неверный тип, пустое name или неверный корень — JsonException. Исходный record не меняйте. null original/json — ArgumentNullException; неверная исходная модель — ArgumentException.

**Пример и ожидаемое поведение**

Profile("Ada","old") + {"bio":null} → Profile("Ada",null); {} оставляет значения.

<a id="11-15"></a>
## 11-15. Каталог с безопасным импортом

Уровень 3 · Прикладная задача · Навык: Сохранение инварианта при ошибке импорта

Создайте Catalog с void Import(string json), string Export() и int Count. JSON — массив объектов {Id:положительный int,Name:непробельная строка}; имена свойств регистрозависимы, лишние поля игнорируются. Id уникальны, порядок массива сохраняется. Пустой массив очищает каталог. null-элемент, null-корень, дубликат, неверные данные — JsonException, null аргумент — ArgumentNullException. Если любая запись неверна, предыдущий каталог полностью сохраняется. Не выдавайте наружу изменяемый список; экспортируйте текущий снимок.

**Пример и ожидаемое поведение**

После Import([{"Id":1,"Name":"A"}]) ошибка импорта с двумя Id=2 оставляет Count=1 и прежний экспорт.
