## 16-01. Границы и мутация условия

Уровень 1 · Проектирование тестов · Навык: Разбиение входов и контрпример ошибочному сравнению

Дан контракт `bool IsPassing(int score)`: значение от 0 до 100 включительно, проходной результат — от 60. Вне диапазона выбрасывается ArgumentOutOfRangeException. Составьте минимальный набор проверок обоих концов диапазона, порога и недопустимых соседей. Реализуйте функцию и покажите, какой тест отличает ошибочное `score > 60` от правильного правила. Не подменяйте проверку исключения возвратом false.

**Пример и ожидаемое поведение**

59 → false; 60 → true; 100 → true; -1 и 101 → исключение.

## 16-02. Общее состояние тестов

Уровень 1 · Чтение кода · Навык: Обнаружение зависимости теста от порядка

Определите две пары результатов для следующего полного фрагмента. Затем перепишите счётчик как объект, чтобы два независимых теста начинались с 1. Не сбрасывайте глобальное состояние в случайном месте.

```csharp
static class Shared
{
    private static int value;
    public static int Next() => ++value;
    public static void Reset() => value = 0;
}
Shared.Reset();
Console.WriteLine($"{Shared.Next()},{Shared.Next()}");
Shared.Reset();
int first = Shared.Next();
Shared.Reset();
Console.WriteLine($"{first},{Shared.Next()}");
```
В обычном Program.Main объявления типа и исполняемый код размещены в своих допустимых местах; здесь они показаны вместе для чтения.

**Пример и ожидаемое поведение**

Первый вывод: 1,2. После сброса перед каждым независимым вызовом: 1,1.

## 16-03. Табличный тест парсера порта

Уровень 1 · Реализация · Навык: Проверка грамматики отдельно от диапазона

Реализуйте `bool TryPort(string? text, out int port)`. Допустимы только от одной до пяти ASCII-цифр, числовое значение 1..65535. Знаки, пробелы, Unicode-цифры и пустая строка запрещены; ведущие нули допустимы. На любом отказе port равен 0. Оформите набор таблицей «вход, успех, значение» и выполните её целиком.

**Пример и ожидаемое поведение**

"00443" → true,443; "65535" → true,65535; "65536", "+80", " 80", "８０", null → false,0.

## 16-04. Регрессия переполнения процента

Уровень 1 · Поиск ошибки · Навык: Воспроизведение дефекта большим граничным входом

Исправьте `double Percent(int done, int total) => 100 * done / total;`. Контракт: 0 ≤ done ≤ total, total от 1 до int.MaxValue; результат — double от 0 до 100 без целочисленного усечения. При нарушении контракта выбрасывайте ArgumentOutOfRangeException. Сначала укажите два независимых дефекта исходной строки, затем добавьте тест, который ловит каждый.

**Пример и ожидаемое поведение**

1 из 4 → 25; 1 из 3 → примерно 33.3333333333; int.MaxValue из int.MaxValue → 100.

Реализуйте `void Commit(Action save, TextWriter output)`: вызвать save ровно один раз, затем записать строку "Сохранено". **Пример и ожидаемое поведение**

## 16-07. Место наблюдения async-ошибки

Уровень 2 · Чтение кода · Навык: Проверка распространения ошибки через await

Предскажите строку результата и объясните, почему добавляется A. Выполните фрагмент в консольном приложении и подтвердите результат автоматической проверкой. Заменять Work на синхронный throw нельзя: это изменило бы эксперимент.

```csharp
static Task<int> Work() => Task.FromException<int>(new IOException("read"));
static async Task<string> Observe()
{
    string trace = "";
    try { Task<int> pending = Work(); trace += "A"; await pending; trace += "X"; }
    catch (IOException) { trace += "B"; }
    return trace;
}
```

**Пример и ожидаемое поведение**

await Observe() → "AB"; символ X не появляется.

## 16-09. Переводы строк в сравнении вывода

Уровень 2 · Поиск ошибки · Навык: Переносимость проверок текста

Тест сравнивает Windows-вывод с литералом `"A\n\nB\n"` и падает. Реализуйте `string NormalizeNewlines(string text)`: CRLF и одиночный CR становятся LF; остальные символы, включая пробелы, пустые строки и завершающий перевод, сохраняются. Строка ненулевая, длина до 10000. Покажите, почему Trim() или удаление всех переводов строки маскируют дефект форматирования.

**Пример и ожидаемое поведение**

## 16-10. Грамматика двух CLI-опций

Уровень 2 · Реализация · Навык: Проверка командной строки как отдельного компонента

Реализуйте `Options Parse(string[] args)`. Опции `--limit N` (целое ASCII 1..100, без знака и пробелов) и `--reverse` могут идти в любом порядке, каждая не более одного раза. По умолчанию limit=10, reverse=false. Неизвестная опция, повтор, пропущенное N и неверный N вызывают ArgumentException. Входной массив и элементы ненулевые, длина до 20. Options — неизменяемая запись с Limit и Reverse.

**Пример и ожидаемое поведение**

["--reverse","--limit","3"] → Options(3,true); [] → Options(10,false); повтор --reverse → ошибка.

## 16-12. Модель очереди и ошибочный стек

Уровень 3 · Проектирование тестов · Навык: Проверка последовательности операций моделью

Постройте тест очереди int на последовательности операций: +4,+7,-,+9,-,-. «+x» добавляет x, «-» извлекает голову. После каждого шага сверяйте число элементов с эталонным List<int>, а при извлечении — значение. Пустое извлечение должно проверяться отдельно как InvalidOperationException. Покажите, что тот же сценарий обнаруживает замену очереди стеком. Вход фиксирован этим условием; писать собственную очередь не требуется.

**Пример и ожидаемое поведение**

## 16-13. Отсутствие JSON-флага и false

Уровень 3 · Поиск ошибки · Навык: Разделение отсутствующего значения и допустимого false

В DTO `public bool Enabled { get; set; }` отсутствующее свойство при десериализации превращается в false, а контракт требует наличие флага. Реализуйте `bool ReadFlag(string json)` для JSON-объекта с полем enabled. true и false допустимы; отсутствующее поле, JSON null и enabled:null вызывают InvalidDataException. Неверный тип и неверный JSON остаются JsonException. Регистр имени свойства не учитывается. Другие поля допускаются.

**Пример и ожидаемое поведение**

{"enabled":false} → false; {} → InvalidDataException; {"enabled":"yes"} → JsonException.

## 16-14. Пакет обновлений без частичного применения

Уровень 3 · Прикладная задача · Навык: Проверка целостности нескольких изменений

Реализуйте `void Apply(Dictionary<string,int> stock, (string Product,int Quantity)[] batch)`. stock уже корректен: непустые уникальные ключи с Ordinal-сравнением, количества 0..100. batch содержит до 100 обновлений: продукт должен существовать в stock, количество 0..100, повтор продукта в одном пакете запрещён. Нулевых входов нет. Обновление заменяет количество; если хотя бы один элемент некорректен, выбрасывается ArgumentException и stock целиком остаётся прежним. Пустой пакет ничего не делает.

**Пример и ожидаемое поведение**

stock={tea:2,milk:1}; batch=[(tea,5),(milk,-1)] → ошибка, stock={tea:2,milk:1}. Валидный пакет [(tea,5)] → tea:5.
