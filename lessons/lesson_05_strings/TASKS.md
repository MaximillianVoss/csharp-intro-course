## 05-01. Безопасное чтение по индексу

Уровень 1 · Реализация · Навык: Проверка null и двух границ индекса UTF-16

Напишите `bool TryChar(string? text,int index,out char value)`.
null или индекс вне [0,text.Length) дают false,value='\0'. Иначе верните true
и кодовую единицу char на этом индексе. Длина строки до 10000, index — любой int.
Здесь индекс намеренно измерен в UTF-16, а не в видимых знаках: половина суррогатной пары
также может быть возвращена как char. Не называйте этот метод чтением целого символа Unicode.

**Пример и ожидаемое поведение**

`TryChar("кот",1,out c)` → true,c='о'; индекс 3 → false,c='\0'.

<a id="05-02"></a>
## 05-02. Середина строки с оговорённым алфавитом

Уровень 1 · Реализация · Навык: Согласование нечётной длины с началом и длиной подстроки

Напишите `string Middle(string text)`. text не null, длина до 10000;
содержит только ASCII-буквы, поэтому один char соответствует одной букве.
Пустая строка даёт пустую строку. При нечётной длине верните одну центральную букву,
при чётной ненулевой длине — две центральных, сохраняя регистр.
Вне ограничений вызовов нет. Используйте Substring, не массив.

**Пример и ожидаемое поведение**

`Middle("abcde")` → `"c"`; `Middle("abcd")` → `"bc"`; `Middle("")` → `""`.

<a id="05-03"></a>
## 05-03. Replace создаёт новое значение

Уровень 1 · Чтение кода · Навык: Неизменяемость string при общем исходном значении

Воспроизведите метод и предскажите результат на banana:
```csharp
public static string Trace(string text)
{
    string original = text;
    string copy = original;
    copy = copy.Replace('a', 'o');
    return original + ":" + copy;
}
```
text не null, длина до 1000, ASCII-буквы. Вне ограничений вызовов нет.
Объясните, почему original не меняется, и что произойдёт, если убрать `copy =` перед Replace.

**Пример и ожидаемое поведение**

`Trace("banana")` → `"banana:bonono"`.

<a id="05-04"></a>
## 05-04. Цифры ASCII вместо всех числовых знаков

Уровень 1 · Реализация · Навык: Явный алфавит протокольной строки

Напишите `bool IsAsciiDigits(string? text)`.
Верните true только для непустой строки, содержащей исключительно ASCII-цифры '0'..'9'.
null, пустая строка, знак, пробелы, точка и цифры других письменностей дают false.
Длина до 10000. Не разбирайте число: строка может быть длиннее диапазона любого целого,
ведущие нули сохраняют допустимость. Объясните, почему char.IsDigit — другой контракт.

**Пример и ожидаемое поведение**

`IsAsciiDigits("007")` → true; `IsAsciiDigits("١٢")` → false.

## 05-05. Первое вхождение без готового поиска

Уровень 1 · Реализация · Навык: Линейный поиск с ранним возвратом индекса

Реализуйте `int FirstIndex(string text,char target)` без IndexOf, Contains и LINQ.
text не null, длина до 10000. Верните индекс первого char, точно равного target,
либо -1. Сравнение кодовых единиц регистрозависимое; индекс измеряется в UTF-16.
Пустая строка допустима. Вне ограничений вызовов нет.

**Пример и ожидаемое поведение**

`FirstIndex("banana",'a')` → `1`; `FirstIndex("banana",'A')` → `-1`.

<a id="05-06"></a>
## 05-06. Нейтральное сравнение команд

Уровень 2 · Реализация · Навык: Явное OrdinalIgnoreCase для технического идентификатора

Напишите `bool SameCommand(string? text,string expected)`.
expected — непустое ASCII-слово из букв; text может быть null или строкой до 1000 символов.
Требуется равенство без различия регистра по StringComparison.OrdinalIgnoreCase.
null даёт false, окружающие пробелы значимы. Не меняйте CurrentCulture и не создавайте
вручную строки в нижнем регистре. Это сравнение технических команд, не сортировка имён людей.

**Пример и ожидаемое поведение**

`SameCommand("StArT","start")` → true; `SameCommand(" start ","start")` → false.

<a id="05-07"></a>
## 05-07. Разделитель остался в результате

Уровень 2 · Поиск ошибки · Навык: Индекс разделителя и начало фрагмента после него

Исправьте код:
```csharp
public static string Broken(string text)
{
    int position = text.IndexOf(':');
    return text.Substring(position);
}
```
Правильный метод `string AfterColon(string text)` возвращает весь текст после первого ':',
не включая сам разделитель. Если ':' нет, верните пустую строку.
text не null, длина до 10000, пустая строка допустима; остальной текст не обрезайте.
Исходный вариант выполните на `name:value` и на строке без двоеточия в ожидаемой проверке отказа.

**Пример и ожидаемое поведение**

`AfterColon("name:value:tail")` → `"value:tail"`; `AfterColon("name:")` → `""`.

<a id="05-08"></a>
## 05-08. Нормализация пробельных промежутков

Уровень 2 · Рефакторинг · Навык: Однопроходная сборка строки без повторного Replace

Реализуйте `string CollapseWhitespace(string text)` одним проходом.
text не null, длина до 10000, корректный UTF-16. Все char, для которых char.IsWhiteSpace=true,
считаются разделителями. Удалите начальные и конечные разделители, каждый внутренний
непустой промежуток замените одним ASCII-пробелом. Непробельные кодовые единицы сохраняйте точно.
Переработайте подход «много раз Replace двойные пробелы», который не обрабатывает табуляцию
и создаёт промежуточные строки. Пользуйтесь StringBuilder: он даёт Append и ToString,
массивы, регулярные выражения и Split не нужны.

**Пример и ожидаемое поведение**

`CollapseWhitespace("  a	\nb  ")` → `"a b"`; только пробелы → `""`.

<a id="05-09"></a>
## 05-09. Неперекрывающиеся вхождения фрагмента

Уровень 2 · Реализация · Навык: Возобновление поиска после найденного фрагмента с гарантией прогресса

Реализуйте `int CountPieces(string text,string needle)`.
text и needle не null, длины до 10000 и 100 соответственно. Пустой needle по договорённости даёт 0.
Посчитайте неперекрывающиеся точные вхождения needle слева направо, сравнивая Ordinal с учётом регистра.
После совпадения следующий поиск начинается сразу после него, а не на следующем char.
Не используйте Replace для подсчёта по разнице длин.

**Пример и ожидаемое поведение**

`CountPieces("aaaaa","aa")` → `2`; `CountPieces("AaA","a")` → `1`.

<a id="05-10"></a>
## 05-10. Поле в кавычках с удвоенным экранированием

Уровень 2 · Реализация · Навык: Лексический разбор кавычек с парным потреблением escape

Реализуйте `bool TryUnquote(string? token,out string value)`.
token длиной до 1000 — одно целиком заключённое в ASCII-кавычки поле: первый и последний char
должны быть '"'. Между ними любой char сохраняется, но каждая внутренняя '"' обязана быть
частью пары `""`, обозначающей одну кавычку в результате. Пустое поле `""` допустимо.
Null, отсутствие внешней пары или одиночная внутренняя кавычка дают false,value="".
Успех возвращает true и декодированное содержимое. Не используйте готовый CSV-парсер;
это грамматика ровно одного поля, не всей CSV-строки.

**Пример и ожидаемое поведение**

Текст `"a""b"` → true, значение `a"b`; текст `"a"b"` → false и пустое значение.

<a id="05-11"></a>
## 05-11. Различающий тест для первого скаляра

Уровень 3 · Проектирование тестов · Навык: Суррогатная пара выявляет ошибку Substring(0,1)

Реализуйте `string FirstScalar(string text)` для не-null корректного UTF-16 длиной до 10000.
Пустой текст даёт ""; иначе верните строку первого скалярного значения Unicode,
используя text.EnumerateRunes() и Rune.ToString(). Не обещайте целую графему.
Напишите тесты, отличающие метод от:
```csharp
public static string Wrong(string text)
{
    return text.Length == 0 ? "" : text.Substring(0, 1);
}
```
Обязательно включите BMP-букву, эмодзи вне BMP и e с комбинируемым акцентом.
Некорректные одиночные суррогаты на вход не подаются.

**Пример и ожидаемое поведение**

`FirstScalar("😀x")` → `"😀"`; `FirstScalar("é")` → `"e"`, не весь знак é.

## 05-12. Префикс из целых текстовых элементов

Уровень 3 · Реализация · Навык: Границы графем в StringInfo вместо char или Rune

Напишите `string TakeElements(string text,int limit)`.
text не null, корректный UTF-16 длиной до 10000; limit от 0 до 10000.
Верните префикс не длиннее limit текстовых элементов по StringInfo в используемой .NET 10.
Если элементов меньше лимита, верните весь текст. Комбинируемые знаки и ZWJ-эмодзи
нельзя резать посередине элемента. Доступны `new StringInfo(text)`, LengthInTextElements
и SubstringByTextElements; массивы индексов не нужны. Не трактуйте результат как число колонок терминала.

**Пример и ожидаемое поведение**

`TakeElements("éx",1)` → `"é"`; `TakeElements("👨‍👩‍👧‍👦x",1)` → весь семейный эмодзи.

## 05-13. Каноническое равенство меток

Уровень 3 · Реализация · Навык: Нормализация FormC перед ordinal-сравнением без потери значимых отличий

Реализуйте `bool SameLabel(string first,string second)`.
Аргументы не null, корректный UTF-16 длиной до 10000. Канонически эквивалентные
Unicode-записи считаются равными; регистр, пробелы и совместимые, но не канонически
эквивалентные знаки различаются. Используйте Normalize(NormalizationForm.FormC),
затем StringComparison.Ordinal. Не используйте FormKC и не убирайте акценты.

**Пример и ожидаемое поведение**

`SameLabel("é","é")` → true; `SameLabel("①","1")` → false; `SameLabel("A","a")` → false.

<a id="05-14"></a>
## 05-14. Число в явно выбранной культуре

Уровень 3 · Реализация · Навык: Разделение пользовательского формата и технического инвариантного формата

Реализуйте `bool TryAmount(string? text,string cultureName,out decimal amount)`.
cultureName по предусловию только `ru-RU` или `en-US`; text — null или строка до 100 символов.
Разрешите ведущий знак, окружающие пробелы и десятичный разделитель выбранной культуры,
но запретите разделители групп и экспоненту. Используйте набор флагов
`AllowLeadingSign | AllowLeadingWhite | AllowTrailingWhite | AllowDecimalPoint`.
Успех требует значение в [-1000000,1000000]. Любой отказ даёт false,amount=0.
Не меняйте CurrentCulture процесса и не заменяйте запятую точкой вручную.

**Пример и ожидаемое поведение**

`TryAmount("1,5","ru-RU",out x)` → true,x=1.5m; та же строка с en-US → false,x=0.

<a id="05-15"></a>
## 05-15. Разбор присваивания с проверкой ключа

Уровень 3 · Прикладная задача · Навык: Срез по первому разделителю и отдельная грамматика технического ключа

Напишите `bool TryAssignment(string? line,out string key,out string value)`.
line — null или корректный UTF-16 длиной до 2000. Строка должна содержать хотя бы один '='.
Разделите её по первому '='; обе части обработайте Trim(). Ключ длиной 1..20 должен начинаться
с ASCII-буквы, остальные char — ASCII-буквы, цифры или '_'. Регистр ключа сохраняется.
Значение может быть пустым и содержать другие '='; кавычки не интерпретируются.
При любом отказе верните false и оба out=""; при успехе true и готовые части.
Выделите `bool IsKey(string text)` и используйте его. Не применяйте Split, словари и регулярные выражения.

**Пример и ожидаемое поведение**

`TryAssignment(" mode = a=b ",out k,out v)` → true,k="mode",v="a=b"; ключ `2mode` → false.
