# Урок 14. LINQ и обработка последовательностей

Для урока нужны коллекции, `IEnumerable<T>`, обобщения, лямбды, делегаты и понятие равенства. Теперь общий обход можно выразить как последовательность операций над данными. После урока вы сможете читать запрос слева направо, предсказывать момент его выполнения и выбирать политику пустоты или дубликатов. Здесь рассматривается LINQ to Objects: источники находятся в памяти или предоставляют обычный `IEnumerable<T>`. Поведение SQL-провайдеров и удалённых запросов отдельно не предполагается.

## 1. Источник, преобразование и результат

LINQ объединяет семейство операций над типизированными последовательностями. `Where` отбирает исходные элементы по предикату, `Select` превращает каждый элемент в новое значение, `OrderBy` задаёт порядок. Операторы комбинируются: выход одного становится входом другого. Используются extension-методы из `System.Linq`; в проектах курса пространство подключено неявными using.

```csharp
int[] result = values
    .Where(x => x % 2 == 0)
    .Select(x => x * x)
    .ToArray();
```

Читаем это как «из values взять чётные, вычислить квадраты, собрать массив». `Where` не меняет значение оставленного числа, `Select` сам по себе не удаляет элементы. Если написать `Select(x => x % 2 == 0)`, получится последовательность логических ответов. Это корректная программа, но она решает другую задачу.

Тип результата каждого шага помогает обнаруживать ошибки. После проекции объекта в имя дальнейший код работает со строкой, поэтому исходные поля уже недоступны. Если для сортировки ещё нужен Score, не выбрасывайте его слишком рано. Удобно сперва сформулировать требуемые данные результата, затем определить, на каком этапе можно безопасно уменьшить модель.

LINQ не отменяет проверки входа. Если значения обязаны лежать в диапазоне, нельзя сначала отфильтровать часть элементов и оставить неверные среди пропущенных незаметными. Иногда полезен предварительный снимок и полная валидация. Цена дополнительной памяти должна соответствовать договору задачи.

## 2. Отложенное выполнение

Большинство преобразующих операторов не выполняют полный запрос при объявлении переменной. Они возвращают объект, который умеет перечислять результат позже. Именно терминальный обход, например `foreach`, `ToArray`, `Count` или `Sum`, запускает вычисление.

```csharp
var list = new List<int> { 1, 2, 3 };
var query = list.Where(x => x > 1);
var saved = query.ToArray();
list.Add(4);
```

В `saved` находятся 2 и 3. Новый обход query увидит также 4, потому что источник изменился до этого обхода. `var` здесь лишь выводит тип переменной; он ничего не говорит о сохранении снимка. Чтобы знать момент исполнения, нужно понимать конкретный оператор.

Повторное перечисление может повторять побочные эффекты предиката и чтение самого источника. `IEnumerable<T>` не обещает, что его можно обойти дважды, что данные останутся одинаковыми или что обход дешёвый. Одноразовый источник способен явно бросить исключение при втором обращении. Поэтому `source.Count()` и затем `source.Sum()` — две разные операции чтения.

Материализация через `ToArray` делает один снимок и позволяет многократную работу с ним. Она требует O(n) памяти и ждёт конца источника, поэтому не подходит бесконечной последовательности или очень большому потоку без отдельного решения. Для поиска первого элемента, напротив, полезно сохранить ленивость и прекратить обход сразу после совпадения.

## 3. Пустота, первый элемент и единственность

Операторы выбора несут разные требования. `First` требует хотя бы одного элемента. `FirstOrDefault` допускает пустоту и возвращает default типа. Для int это 0, поэтому отсутствие совпадения смешивается с настоящим нулём. Проекция в `int?` до выбора меняет default на null и сохраняет различие:

```csharp
int? first = numbers.Where(x => x % 2 == 0)
    .Select(x => (int?)x)
    .FirstOrDefault();
```

Преобразование в nullable после `FirstOrDefault<int>` опоздало бы: информация уже потеряна. В первом варианте каждый найденный int становится ненулевым nullable-значением, а пустота остаётся null. Такой порядок операций следует из смысла результата.

`SingleOrDefault` выражает другой договор: совпадений должно быть не более одного. Отсутствие допустимо, второе совпадение означает ошибку. Подмена на FirstOrDefault скрывает нарушение уникальности. Тесты поэтому охватывают три разных класса: ноль, одно и два совпадения, желательно с формами ключа, которые равны согласно выбранному comparer.

`All` на пустом наборе возвращает true: нет элемента, который нарушал бы правило. Это не ошибка библиотеки. Если приложение требует «есть хотя бы один участник и все сдали», непустота добавляется отдельно. `Any` отвечает лишь о существовании хотя бы одного подходящего элемента и не заменяет All. Не меняйте математическое значение оператора в объяснении; уточняйте бизнес-требование.

## 4. Упорядочивание и страницы

`OrderBy` задаёт главный ключ по возрастанию, `OrderByDescending` — по убыванию. Следующие ключи добавляют через `ThenBy` и `ThenByDescending`. Второй самостоятельный OrderBy создаёт новый главный порядок, поэтому часто уничтожает смысл первого. Рейтинг «балл вниз, имя вверх» требует именно ThenBy для имени.

Для строк указывайте правило сравнения, если результат должен быть одинаковым при разных культурах. `StringComparer.Ordinal` сравнивает по точным значениям, а `OrdinalIgnoreCase` дополнительно игнорирует регистр. Это не полная языковая нормализация слова. Если задача требует обрезать пробелы и привести к нижнему регистру, такой шаг выполняется отдельно и явно.

Сортировка LINQ to Objects стабильна: равные ключи сохраняют исходный порядок элементов. Проверить это на двух одинаковых числах нельзя — перестановка незаметна. Используйте разные объекты с одинаковыми ключами и различимыми метками либо проверяйте идентичность ссылок. Для record-объектов равенство по содержимому может также скрыть перестановку.

`Skip` и `Take` задают страницу, но сами не сортируют источник. При нумерации с единицы смещение равно `(page-1)*pageSize`; вычисляйте его checked после валидации параметров. Для обычного IEnumerable Skip может пройти весь пропускаемый префикс, поэтому далёкая страница не обязана получаться за O(pageSize). Пустая страница за концом источника обычно является нормальным результатом.

## 5. Группы и свёртки

`GroupBy` собирает элементы с одинаковым ключом. Каждая группа имеет Key и последовательность исходных элементов. После группировки удобно вычислять Count, Sum, Average или свою модель отчёта. Если требуется нормализация, она должна происходить до группировки, иначе `" Cat "` и `"cat"` окажутся разными ключами.

Для частот слов цепочка может нормализовать каждое слово один раз, убрать пустые и сгруппировать по нормализованной строке. Чтобы порядок отчёта не зависел от первого появления ключа, добавляют явный OrderBy. Группировка не означает сортировку ключей, это независимые операции.

`Aggregate` — общая свёртка: на каждом шаге новое состояние получается из старого и текущего элемента. Начальное состояние, или seed, определяет результат пустоты. Пара `(Units:0L,Total:0m)` позволяет за один проход посчитать число единиц и стоимость корзины. Внутри шага можно проверить строку и использовать checked для сложения.

Не все средние можно складывать. Среднее двух средних без учёта размеров групп обычно не равно среднему всех элементов. Если отчёт требует среднюю длительность всех запросов, вычисляйте Average над всей нужной группой. Фильтрация только ошибочных запросов перед GroupBy незаметно изменила бы знаменатель и число запросов. Сначала точно определите множество, к которому относится агрегат.

## 6. Соединение, разворачивание и дубликаты

`Join` сопоставляет элементы двух последовательностей по ключам и возвращает только пары совпадений. Заказ без известного клиента исчезнет из inner join. Если справочник клиентов содержит два одинаковых ключа, заказ может размножиться. Поэтому инвариант уникальности справочника проверяется отдельно, если он требуется моделью.

`GroupJoin` сохраняет каждый внешний элемент и предоставляет всю группу совпавших внутренних. Для клиента без покупок группа пуста; Count даёт 0, decimal Sum — 0. Это естественная форма отчёта, в котором клиенты без заказов тоже обязаны присутствовать. Выбор внешнего источника определяет, что именно сохраняется при отсутствии пары.

`SelectMany` разворачивает вложенные последовательности в одну. Индексированные перегрузки Select и SelectMany помогают сохранить координаты исходных строк и столбцов. Пустой ряд не создаёт выходных элементов, но не должен перенумеровывать последующие ряды. Это отличается от простой проекции, которая вернула бы последовательность массивов.

`ToDictionary` требует уникальных ключей и не выбирает «последнюю» запись автоматически. Если источник хранит ревизии, сначала задайте политику: максимальная версия, при её равенстве последняя запись входа. Для проверки такого правила полезны три кандидата: старая версия, две одинаково новые и более поздняя по позиции, но младшая по версии. Решение с обычным Last на группе тогда будет обнаружено.

## 7. Сложность, количество обходов и диагностика

Фильтрация и простая проекция обычно проходят элементы один раз. Поиск первого совпадения способен остановиться раньше. Полная сортировка требует накопить данные и обычно занимает O(n log n). Группировка и соединение используют дополнительную память; несколько вызовов над одной уже построенной группой не означают повторного чтения исходного одноразового источника, но всё равно имеют свою стоимость.

Не оценивайте сложность по числу строк запроса. Короткое выражение с Count, затем Sum над исходником может читать его дважды. Сложный на вид Aggregate иногда делает один проход и хранит лишь пару чисел. Материализация обменивает память на предсказуемость снимка. Лучший выбор определяется размером данных и нужным контрактом, а не запретом циклов как таковых.

При отладке смотрите тип промежуточного результата и момент перечисления. Исключение в предикате может возникнуть на ToArray, хотя ошибочное выражение написано несколькими строками выше. Сохраняйте маленькие промежуточные массивы на время расследования и проверяйте значения, но после исправления осознанно решайте, нужны ли все эти снимки в итоговом алгоритме.

Для тестов используйте источник, который считает или запрещает повторное перечисление, источник с опасным хвостом после первого совпадения и tagged-объекты для стабильности. Такие проверки фиксируют поведение напрямую и не требуют ненадёжных измерений времени. Они также объясняют, чем два запроса, дающие одинаковый ответ на маленьком массиве, различаются по существу.

## 8. Самопроверка и ответы

Попробуйте заранее ответить: почему query изменился после Add; чем SingleOrDefault сильнее FirstOrDefault; что возвращает All на пустоте; почему ThenBy отличается от второго OrderBy; как получить клиентов без покупок.

Ответ 1. Query хранит описание будущего обхода и источник, а ToArray создаёт снимок в момент вызова. Новый обход читает обновлённый список. Изменение уже материализованного массива таким способом не происходит.

Ответ 2. SingleOrDefault проверяет отсутствие второго совпадения. FirstOrDefault прекращает поиск после первого и не подтверждает уникальность. Поэтому для инварианта уникального имени обязателен тест с двумя равными по comparer именами.

Ответ 3. All возвращает true: не существует нарушающего элемента. Требование непустой группы проверяется отдельно. Это дополнительное условие предметной области, а не иной вариант поведения All.

Ответ 4. ThenBy уточняет существующий порядок, а OrderBy начинает новый главный. При точном равенстве всех ключей стабильность сохраняет исходную последовательность объектов. Контрольные данные должны делать оба уровня сортировки наблюдаемыми.

Ответ 5. Используйте клиентов как внешний источник GroupJoin. Каждому клиенту соответствует группа покупок, которая может быть пустой. Агрегаты по пустой группе дают нули, и клиент остаётся в отчёте.

Официальная справка: [введение в запросы LINQ](https://learn.microsoft.com/en-us/dotnet/csharp/linq/get-started/introduction-to-linq-queries). Условия в задачнике не содержат готовых ответов; решения отдельно показывают запросы, причины выбора операторов и исполняемые проверки.
