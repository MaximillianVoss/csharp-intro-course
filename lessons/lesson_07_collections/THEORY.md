# Модуль 07. Коллекции и выбор структуры данных

## 1. Сначала операции, затем тип коллекции

Нужны массивы, циклы, методы и сравнение строк. После модуля вы сможете выбирать структуру по требуемым операциям, а не по знакомому названию. Маршрут: запустить [пример](examples/Program.cs), разобрать таблицу выбора, решить [задачи](TASKS.md) без подсматривания, затем сравнить поведение с [подробными решениями](SOLUTIONS.md). LINQ пока не требуется: каждый обход остаётся явно видимым.

Массив обеспечивает фиксированное число ячеек. Когда записи добавляются, удаляются или ищутся по ключу, полезны коллекции. Но универсальной «лучшей коллекции» нет. Для очереди обслуживания важен порядок поступления, для истории отмены — обратный порядок, для списка покупок — возможность повторов, для множества разрешённых кодов — быстрый ответ о наличии.

| Требование | Подходящий тип | Существенная операция |
|---|---|---|
| Порядок и доступ по индексу | `List<T>` | `Add`, `Insert`, индексатор |
| Значение по уникальному ключу | `Dictionary<TKey,TValue>` | `TryGetValue`, индексатор |
| Уникальность и членство | `HashSet<T>` | `Add`, `Contains`, `Remove` |
| Первый пришёл — первым вышел | `Queue<T>` | `Enqueue`, `Dequeue` |
| Последний пришёл — первым вышел | `Stack<T>` | `Push`, `Pop` |

Эту общую классификацию полезно сопоставить с [рекомендациями Microsoft по выбору коллекции](https://learn.microsoft.com/en-us/dotnet/standard/collections/selecting-a-collection-class). Для наших задач важнее самостоятельно вывести выбор из контракта: нужны ли повторы, значим ли порядок, кто и как извлекается следующим.

Буква `T` обозначает тип элемента. `List<int>` хранит числа, `List<string>` — строки. В `Dictionary<string,int>` строка служит ключом, число — значением. Здесь мы используем готовые обобщённые типы библиотеки; собственные обобщённые классы появятся позднее. Сокращение `List<int> values = new();` берёт тип создаваемого объекта из левой части; полная форма `new List<int>()` равнозначна.

## 2. List: размер, вместимость и изменение индексов

`Count` — число существующих элементов. `Capacity` — вместимость внутреннего хранилища до следующего расширения. Большая вместимость не создаёт доступных элементов. После `new List<int>(100)` список пуст, поэтому индекс ноль ещё недопустим. Для чтения и замены граница та же, что у массива: от нуля до `Count-1`.

При вставке возникает ещё одна допустимая позиция: `Count` означает место после последнего элемента. `Insert(0,value)` вставляет в начало, `Insert(Count,value)` — в конец. Вставка между существующими элементами сдвигает правую часть. Поэтому индекс, запомненный до вставки, может начать обозначать другой элемент. Идентификатор записи и позиция в списке — разные понятия.

```csharp
List<int> values = new() { 10, 30 };
values.Insert(1, 20); // [10,20,30]
values.RemoveAt(0);  // [20,30]
values.Add(40);      // [20,30,40]
```

Удаление при прямом обходе требует внимания. В `[-1,-2,3]` после удаления индекса ноль число `-2` сдвигается на ноль. Если цикл увеличит индекс до единицы, отрицательный сосед будет пропущен. Обход с конца избегает пропуска: сдвигаются только уже проверенные элементы. Однако стоимость отдельных сдвигов остаётся, поэтому много удалений может потребовать квадратичное время.

`foreach` удобен для чтения. Изменение самой коллекции во время такого перечисления обычно нарушает работу перечислителя; не используйте его как скрытый индексный цикл с удалениями. Если нужно изменить содержимое, выберите явную стратегию: обратный проход, уплотнение, создание нового результата. Выбор зависит также от права менять исходник.

Копия `new List<int>(source)` содержит независимый набор чисел. Присваивание `copy=source` копирует ссылку и оставляет один объект. Для списка изменяемых объектов конструктор копирует ссылки на элементы, а не весь граф данных. Об этом важно помнить даже до изучения собственных классов: структура коллекции и независимость её элементов — разные уровни.

## 3. Dictionary: ключ, значение и равенство

Словарь хранит соответствие ключа значению. По ключу удобно найти остаток товара, число повторов кода или список позиций метки. Один ключ соответствует одному значению; присваивание по существующему ключу заменяет его значение, а не добавляет вторую запись. Если повторяющиеся ключи должны накапливать данные, это нужно написать явно.

```csharp
Dictionary<string, int> counts = new(StringComparer.OrdinalIgnoreCase);
foreach (string code in new[] { "ab", "AB", "x" })
{
    counts.TryGetValue(code, out int previous);
    counts[code] = previous + 1;
}
// counts["aB"] == 2, counts["X"] == 1
```

`TryGetValue` сообщает наличие через `bool`, а найденное значение передаёт в `out`-переменную. Для нового целочисленного счётчика при отсутствии получается ноль. Это удобно именно для частот. Вообще ноль может быть настоящим значением, поэтому нельзя определять наличие только по содержимому `out`: всегда учитывайте возвращённый `bool`.

Равенство строк является частью модели. `Ordinal` различает регистр, `OrdinalIgnoreCase` игнорирует его без зависимости от текущей культуры. Если по условию `ab` и `AB` — один технический код, компаратор нужно задать при создании словаря. Ручное преобразование в нижний регистр не должно незаметно зависеть от настроек компьютера. Для человеческих текстов правила сравнения могут быть другими, но их тоже следует оговорить.

Не обещайте порядок ключей, если он не является частью выбранного контракта. Даже наблюдаемый в конкретном запуске порядок не заменяет явно заданный порядок результата. Если требуется отсортированный отчёт, отдельно получите ключи и отсортируйте их. Если нужен порядок первого появления, храните его в предназначенной для этого последовательности.

Словарь списков представляет группировку. Для каждого нового ключа создаётся собственный `List<int>`, куда добавляются найденные индексы. Один список, созданный перед циклом и отданный всем ключам, приведёт к общему смешанному содержимому. Эта ошибка связана со ссылками, а не с самой идеей словаря.

## 4. HashSet: уникальность не равна любой фильтрации

Множество отвечает на вопрос о принадлежности и хранит каждое значение один раз по своему правилу равенства. `Add` возвращает `true`, только если элемент действительно появился впервые. `Remove` возвращает `true`, только если элемент существовал и был удалён. `Contains` ничего не меняет. Эти три операции внешне похожи, но позволяют решить разные задачи.

Для уникальных элементов в порядке появления используйте `HashSet` как память о встреченных значениях и `List` как результат. Успешный `Add` разрешает добавить значение в список. На `[4,2,4,3,2]` получится `[4,2,3]`. Перечислять само множество для восстановления заданного порядка не требуется.

Для уникального пересечения в порядке левого массива удобно построить множество правого. Успешный `Remove` означает, что значение было справа и ещё не выдавалось. После первого совпадения оно исчезает из множества, поэтому повтор слева ничего не добавит. Для левого `[4,2,4]` и правого `[2,4]` ответ `[4,2]`.

Для фильтра разрешённых запросов нужен `Contains`, а не `Remove`: повторные запросы должны сохраниться. На том же левом `[4,2,4]` при разрешённых `[2,4]` ответ уже `[4,2,4]`. Смена одной операции меняет контракт, поэтому похожая форма цикла не означает одинаковую учебную задачу. Прежде чем выбирать метод множества, решите судьбу повторов.

Обычное множество также не подходит для сравнения мультимножеств. `[1,1,2]` и `[1,2,2]` содержат одинаковые уникальные числа, но разную кратность. Здесь нужен словарь частот. После подсчёта первого входа второй погашает имеющиеся количества. Невозможность погасить очередное вхождение доказывает различие.

## 5. Queue и Stack моделируют порядок действий

Очередь работает по FIFO: самым ранним извлекается тот, кто дольше всего ждёт. Стек работает по LIFO: следующим извлекается последний добавленный. Оба типа намеренно ограничивают произвольный доступ. Такая ограниченность помогает выразить алгоритм и не перепутать его правила с обычным индексным списком.

В очереди `Peek` показывает следующий элемент, не удаляя его; `Dequeue` удаляет и возвращает. В стеке аналогичные роли выполняют `Peek` и `Pop`. Перед обычным извлечением нужно учитывать пустоту. Там, где отсутствие ожидаемо, библиотечные `TryDequeue` и `TryPop` возвращают `false` вместо необходимости работать с исключением. Значение ноль при неуспехе само по себе не означает, что такой элемент был в коллекции.

Очередь позволяет организовать круговое обслуживание. Незавершённая работа после одного кванта возвращается в хвост, завершённая удаляется навсегда. Храните индекс работы, если одинаковые длительности принадлежат разным работам. Одна только длительность не позволяет затем сообщить, кто именно завершился.

Стек естественно описывает незакрытые скобки: последняя открытая должна закрыться первой. Просто подсчитать число круглых и квадратных скобок недостаточно. У `([)]` количества совпадают, но порядок неверен. При закрывающей скобке нужен непустой стек и совпадение типа его вершины. В конце стек обязан быть пустым.

Для отмены и повторения используются два стека снимков. Перед новым изменением текущее значение сохраняют в `undo`, а `redo` очищают. Отмена переносит текущее значение в `redo` и забирает прошлое из `undo`; повтор делает обратное. Новое изменение после отмены создаёт другую ветвь истории, поэтому старое будущее нельзя сохранять как допустимый повтор.

## 6. Составные алгоритмы и сохранение состояния

Коллекции часто комбинируются. При резервировании нескольких товаров словарь остатка даёт быстрый поиск, но не обеспечивает успешность операции целиком. Если списывать товары по мере проверки, поздняя недостача оставит ранние списания. Правильный учебный алгоритм сначала проверяет все запросы, затем применяет их. Это две логические фазы, а не два несвязанных цикла ради количества кода.

Такой метод обеспечивает целостность при оговорённом однопоточном использовании. Он не становится автоматически транзакцией для параллельной программы. Если другая операция изменяет склад между фазами, потребуется отдельная синхронизация. В этом модуле подобных конкурентных изменений нет; важно точно обозначать границы доказанной корректности.

Очередь также даёт поиск кратчайшего пути по равномерной сетке. Сначала посещается старт, затем все клетки на расстоянии один, затем два и так далее. Расстояние записывают при постановке клетки в очередь, чтобы соседние клетки не добавили её несколько раз. Стек обошёл бы сетку другим порядком и не дал бы той же гарантии первого кратчайшего пути.

Матрица расстояний первоначально заполнена `-1`: клетка ещё не посещена. Ноль означает старт, поэтому эти значения нельзя смешивать. Координаты можно хранить одним индексом `row*columns+column`, восстанавливая их делением и остатком. Каждое из четырёх направлений проверяет собственные границы. Диагональные переходы не добавляют без требования условия.

В оценке сложности учитывайте построение индекса. Замена внутреннего поиска на `HashSet.Contains` полезна, когда множество строится один раз, а запросов много. Если создавать множество заново для каждого запроса, выигрыш исчезнет. Для хешированных коллекций здесь используем ожидаемую стоимость операций; это точнее безусловного обещания одинакового времени при любых данных.

## 7. Как проектировать различающие проверки

Проверка должна замечать конкретное неверное решение. Для FIFO добавьте хотя бы два различных значения и перемежайте извлечение с добавлением. Для компаратора строк нужны разные регистры одного кода. Для уникального пересечения нужны повторы с обеих сторон. Для фильтра разрешённых значений, напротив, повтор во входе должен остаться.

Для операций, обещающих отказ без изменений, сохраните наблюдаемое состояние и проверьте его после отказа. Недостаточно утверждения `result==false`: склад мог уже потерять часть товара. Для независимых групп измените один список и убедитесь, что соседняя группа не изменилась. Для исходных коллекций проверяйте сохранность там, где контракт запрещает мутацию.

Самостоятельно ответьте: почему `Capacity=100` не разрешает читать `list[99]`? Что различают `Add`, `Remove`, `Contains` в трёх задачах с множеством? Почему два равных множества не доказывают равенство кратностей? Почему `redo` очищается после нового изменения? Почему посещение в поиске пути отмечается при добавлении в очередь?

## 8. Ответы самопроверки

**Вместимость и размер.** Capacity резервирует место для будущих записей, но не создаёт логических элементов. Границу индексного доступа задаёт Count. Для пустого списка даже вместимость миллион не делает индекс ноль допустимым. Добавление через Add сначала создаёт элемент и увеличивает Count.

**Три операции множества.** Add различает впервые встреченное значение; Remove различает первое разрешённое совпадение и одновременно запрещает повторную выдачу; Contains только проверяет принадлежность и поэтому сохраняет повторы запросов. Их нельзя менять местами ради внешне одинакового цикла: получится другая семантика результата.

**Кратность.** Преобразование в множество теряет число появлений. У обоих входов `[1,1,2]` и `[1,2,2]` множество равно `{1,2}`, но второй экземпляр единицы заменить нечем. Словарь частот сохраняет именно ту информацию, которую потеряло множество. Равенство длин отдельно не восстанавливает её.

**Очистка будущего.** После отмены значения 8 до 4 история допускает повтор 8. Если затем установить 7, текущая ветвь уже другая. Повтор старого 8 внезапно перескочил бы через новое изменение. Поэтому новая команда очищает redo, даже если устанавливает значение, совпадающее с текущим: контракт описывает историю действий.

**Посещение при постановке.** Пока клетка ждёт извлечения, несколько соседей могут обнаружить её повторно. Немедленная запись расстояния устраняет дубликаты в очереди. Благодаря обработке слоями первый найденный маршрут уже имеет минимальную длину; улучшать его последующим маршрутом в равномерной сетке не потребуется.
