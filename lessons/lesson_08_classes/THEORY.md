# Модуль 08. Классы, свойства и согласованное состояние

## 1. Зачем объединять данные с операциями

Предполагаются методы, массивы и стандартные коллекции. Здесь появляется собственная модель: объект хранит данные и предоставляет операции, сохраняющие их смысл. Начните с [запускаемого примера](examples/Program.cs), затем последовательно переходите от счётчика к корзине и переносу между контейнерами в [задачнике](TASKS.md). [Разборы](SOLUTIONS.md) открывайте после собственного решения и проверки отказов.

У набора открытых переменных нет единого хозяина. Если ширина, высота и площадь изменяются из разных мест, они могут перестать соответствовать друг другу. Класс позволяет установить границу: внешняя программа выражает намерение, например изменить размеры, а сам объект решает, допустимо ли это изменение и какие поля нужно обновить.

Инвариант — утверждение о корректном состоянии объекта. У кошелька баланс неотрицателен; у контейнера количество не превосходит вместимость; у дроби знаменатель положителен и взаимно прост с числителем. Конструктор устанавливает инвариант, публичные методы обязаны сохранять его. Проверка только одной операции недостаточна, если другое открытое свойство позволяет обойти ограничения.

В заданиях этого модуля конструкторы с явно указанными предусловиями получают допустимые аргументы. Это сознательная учебная граница. Попытки изменения с ожидаемым отказом выполняются через методы `Try...`, возвращающие `bool`. Проверку нарушенных предусловий через исключения подробно изучим в модуле 10. Не переносите учебное предусловие в описание промышленного API как готовую защиту от любого входа.

## 2. Поле, свойство, конструктор и доступность

Поле хранит значение внутри объекта. Свойство предоставляет контролируемый способ его читать или менять. Методы описывают действия. Конструктор вызывается при создании и задаёт начальные данные. Модификатор `public` разрешает обращение внешнему коду, `private` оставляет член доступным только внутри содержащего типа.

```csharp
public sealed class Wallet
{
    public decimal Balance { get; private set; }

    public Wallet(decimal initialBalance)
    {
        Balance = initialBalance;
    }

    public bool TrySpend(decimal amount)
    {
        if (amount <= 0 || amount > Balance) return false;
        Balance -= amount;
        return true;
    }
}
```

Снаружи доступно чтение `Balance`, но присваивание запрещено компилятором. Изменение возможно через `TrySpend`, где находятся правила. Слово `sealed` запрещает наследование от данного класса; пока оно помогает не вводить дополнительных путей изменения поведения. Наследование и полиморфизм будут следующей темой.

`get;` без `set` задаёт свойство, значение которого в обычном случае устанавливают при создании. Оно подходит для вместимости контейнера и неизменяемого кода. `private set` подходит для баланса или текущего состояния: менять их может сам класс. Вычисляемое свойство `Area => Width * Height` не хранит вторую копию площади и всегда использует текущие размеры.

Параметр и поле могут иметь одинаковое имя. В записи `this.value = value` слева находится поле текущего объекта, справа — параметр. `this` помогает устранить неоднозначность, но не создаёт объект. Каждое `new Wallet(...)` создаёт отдельный кошелёк; обращение к методу выполняется для конкретного экземпляра.

Не объявляйте все поля публичными ради краткости. Тогда внешний код сможет присвоить отрицательный баланс, не вызвав ни одной проверки. При этом добавление свойств с полностью открытыми `get; set;` само по себе тоже не создаёт инкапсуляцию. Важно, какие состояния и переходы фактически доступны через публичную границу.

## 3. Отказ должен сохранять объект

Рассмотрим прямоугольник с допустимыми размерами от нуля до миллиона. Если метод сначала записал новую ширину, а затем обнаружил недопустимую высоту, возвращённый `false` не означает сохранность состояния. Для операции «изменить размеры вместе» нужны две фазы: проверить оба аргумента, затем сделать оба присваивания.

То же правило работает при взаимодействии объектов. Для переноса товара сначала проверяют неотрицательность количества, наличие в источнике и свободное место в получателе. Только после всех проверок уменьшают один остаток и увеличивают другой. Ошибка после первого изменения оставила бы общее количество несохранённым.

Арифметику также проверяют до опасной операции. Для резервуара условие `amount > Capacity - Volume` безопаснее проверки `Volume + amount > Capacity`, когда `amount` может быть `int.MaxValue`. При корректном состоянии свободное место неотрицательно и помещается в `int`, а сумма с внешним аргументом до проверки способна переполниться.

Ожидаемый отказ не всегда является исключительной ситуацией. Недостаточный баланс или полная ёмкость — обычные исходы бизнес-операции. Возвращаемый `bool` делает их видимыми без нарушения потока выполнения. Вызывающий обязан проверить результат. Если проигнорировать `false`, интерфейс объекта может быть безопасным, а сценарий пользователя всё равно будет неверным.

После отказа проверяйте и результат, и состояние. Для кошелька после неудачной траты баланс должен остаться прежним. Для изменения размеров нужно проверить обе координаты. Для переноса — оба контейнера. Значения, лежащие ровно на допустимой границе, помогают отличить `>` от `>=` и предотвращают случайное исключение разрешённого случая.

## 4. Ссылочные и значимые типы

Переменная класса хранит ссылку на объект. Присваивание второй переменной копирует ссылку, поэтому две переменные могут наблюдать один и тот же объект. Переменная структуры хранит значение структуры; присваивание копирует её поля. Различие относится к семантике операций, а не к упрощённому утверждению «всё класса всегда в одном месте памяти, всё структуры — в другом».

```csharp
Box first = new() { Number = 1 };
Box alias = first;
alias.Number = 8;
// first.Number тоже равен 8

Point p = new(2, 3);
Point q = p;
q = q with { X = 9 };
// p.X равен 2, q.X равен 9
```

Здесь `Box` — класс с изменяемым числом, `Point` — `readonly record struct`. Новый объект Box не создавался при присваивании alias. Новое значение Point появляется при копировании и при выражении `with`. Для доказательства общего объекта существует `ReferenceEquals`, но его не следует путать с равенством данных.

Содержимое структуры может включать ссылки. Если в `Snapshot` лежат `int Revision` и `int[] Values`, копирование структуры разделяет числовое поле, но сохраняет общую ссылку на массив. Изменение `copy.Revision` не трогает исходник, а `copy.Values[0]` меняет общий массив. Для независимого снимка массив нужно копировать отдельно.

Из этого следует важный вопрос при проектировании копирования: что должно стать независимым? Копия ссылки, копия верхнего объекта и глубокая копия достижимых изменяемых объектов — разные обещания. Название `Clone` или `with` само по себе не отвечает на вопрос о всём графе данных. В условии задачи глубина независимости должна быть определена явно.

Статическое поле принадлежит типу, а экземплярное — отдельному объекту. Если остаток каждого измерителя случайно объявлен `static`, все измерители станут делить один счётчик. Обнуление такого поля в конструкторе не исправляет модель: создание нового измерителя сотрёт данные уже существующих. Правильное решение — выбрать соответствующую область хранения.

## 5. Record и неизменяемые представления

Запись `record` удобна для моделей, где важны данные и сравнение по их компонентам. Обычный `record` является ссылочным типом, а `record struct` — значимым. Позиционная запись может автоматически предоставить свойства и операции сравнения. Официальные особенности и поверхностное копирование описаны в [справочнике Microsoft о record](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/record).

```csharp
public sealed record Product(string Code, string Title, decimal Price);

Product original = new("A", "Книга", 100m);
Product changed = original with { Price = 120m };
Product sameData = original with { Price = 100m };
// original.Price == 100; changed.Price == 120
// original == sameData, но ReferenceEquals(original, sameData) == false
```

Равенство данных и тождественность объектов отвечают на разные вопросы. Два товара с одинаковыми компонентами здесь равны как записи, хотя созданы отдельно. Если идентичность товара в другой модели определяется только Code, позиционное равенство всех трёх полей не обязательно соответствует бизнес-смыслу. Тип не выбирают только по краткости объявления.

Неизменяемость верхних свойств не гарантирует неизменяемость вложенных объектов. Record со свойством `List<int>` всё ещё может содержать изменяемый список. В нашей записи товара строковые компоненты и decimal позволяют избежать такого скрытого изменения. При добавлении массивов и списков потребуется отдельно определить владение ими.

Фабрика может возвращать `Product?`, когда новая цена недопустима. Знак вопроса означает, что результат может быть `null`. Перед доступом к свойствам нужно проверить наличие объекта. Оператор `!` подавляет предупреждение анализа nullable, но не выполняет проверку во время работы. В решениях он встречается после подтверждённого условия теста или для заведомо допустимого фабричного входа; заменять им проверки пользовательских данных нельзя.

## 6. Композиция, снимки и каноническая форма

Композиция означает, что объект содержит другие объекты, которым поручены части работы. Корзина содержит строки, строка знает цену и количество, её итог равен произведению. Корзина суммирует итоги и контролирует добавление. Здесь естественно отношение «содержит», а не «является»: корзина не является строкой и не должна наследоваться от неё.

Внутренняя коллекция принадлежит объекту. Если вернуть изменяемый `List` наружу, внешний код сможет вызвать Clear и обойти правила. Поле `readonly` запрещает переназначение ссылки, но не запрещает менять список. Для каталога строк удобно возвращать массив-снимок: вызывающий может заменить его элементы, не затронув внутреннее хранилище.

Цена снимка — копирование. При `n` заголовках создание массива требует `O(n)` времени и памяти. Для строк это копирование ссылок безопасно относительно изменения самих строк, потому что строки неизменяемы. Для изменяемых объектов потребуется другое решение. Экономия копирования допустима только при столь же ясном контракте доступа.

Иногда инвариант удобнее обеспечить ещё при создании. У `TimeSlot` конструктор закрыт, а фабрика разрешает только `start<end`. Тогда каждый успешно созданный интервал имеет положительную длину. Полуинтервалы `[start,end)` пересекаются, когда оба начинаются раньше завершения другого. Касание границ не считается пересечением: встреча до 11:00 не конфликтует со следующей с 11:00.

Каноническая дробь показывает другую пользу фабрики. Знаменатель делают положительным, затем числитель и знаменатель делят на НОД. Числа `6/-8` и `-3/4` получают одинаковые компоненты. Нулевой числитель превращается в `0/1`. Так уменьшается количество разных представлений одного математического значения, а последующие операции становятся понятнее.

## 7. Состояния, отладка и вопросы

Не вся модель сводится к числовому диапазону. Заказ проходит состояния Draft, Submitted, Cancelled. Перечисление `enum` называет конечные варианты, а методы контролируют переходы между ними. Повторная отправка и действия после отмены по нашему контракту отклоняются. Открытый setter состояния позволил бы внешнему коду воскресить отменённый заказ.

При отладке найдите место, где состояние стало неверным, а не только место, где оно обнаружилось. Поставьте остановку перед публичной операцией, запишите её вход и исходные свойства, затем наблюдайте каждую запись. Для двух объектов используйте различимые значения и проверьте `ReferenceEquals`, если подозреваете общий объект. Для общей коллекции измените один наблюдаемый путь и проверьте второй.

Самостоятельно ответьте: чем `private set` полезнее открытого setter? Почему вычисляемая площадь проще хранения дополнительного поля? Как структура может оставить общий массив? Почему readonly-список не защищает каталог? Когда два равных record могут быть разными объектами? Какие состояния надо проверить после неудачного переноса товара?

## 8. Ответы самопроверки

**Закрытый setter.** Он переносит право изменения внутрь класса. Внешний код получает результат чтения и вызывает смысловую операцию, где можно проверить правила. Однако сам по себе private set не делает любую внутреннюю операцию правильной: каждый метод всё равно обязан сохранять инвариант.

**Вычисляемая площадь.** Если площадь является чистой функцией текущих размеров, отдельное поле дублирует информацию. При изменении ширины легко забыть обновить кэш. Вычисляемое свойство устраняет такое рассогласование. Для дорогих вычислений кэш бывает полезен, но требует отдельного протокола актуальности, которого здесь не нужно.

**Структура с массивом.** Копируются поля, а значение поля-массива — ссылка. Получаются две структуры с отдельными скалярными полями и одной общей внутренней последовательностью. Для DeepCopy нужно скопировать массив. Если его элементы также изменяемые объекты, глубину копирования необходимо определить ещё дальше.

**Readonly и список.** Запрет переназначения поля не запрещает Add, Clear и замену элементов самого объекта List. Возврат этой ссылки раскрывает внутреннюю коллекцию. Независимый снимок защищает набор заголовков, потому что замена ячейки снимка не меняет внутренний список каталога.

**Равные записи.** Два отдельно созданных Product с одинаковыми Code, Title и Price равны по данным. Выражение with при неизменённых компонентах также создаёт отдельный объект с равными данными. ReferenceEquals при этом ложен. Проверка баланса или бизнес-идентичности не должна случайно подменяться проверкой ссылки.

**Неудачный перенос.** Нужно подтвердить false, прежнее количество источника, прежнее количество получателя и сохранённую общую сумму. Отдельно проверяются перенос нуля и перенос в тот же объект: это не два независимых контейнера, поэтому обычная проверка свободного места не должна запрещать допустимый перенос в себя.
