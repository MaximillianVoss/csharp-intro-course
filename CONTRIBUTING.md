# Изменение учебного курса

1. Уточните проверяемый навык и контракт задачи.
2. Редактируйте источник условия и разбора в lessons/lesson_*/tasks.json.
3. Редактируйте реализацию в solutions/TaskNN.cs и связанный пример, если он затронут.
4. Добавьте различающий сценарий в Run. Для ошибок нужен тест, который падал до исправления.
5. Выполните python tools/render_course.py --strict.
6. Выполните pwsh -NoProfile -File tools/Verify.ps1.
7. Выполните python tools/audit_course.py; просмотрите подозрительные пары по смыслу.
8. Обновите решения аудита в docs/SEMANTIC_REVIEW.json для изменившихся кандидатов.

render_course.py генерирует оглавления, TASKS.md, SOLUTIONS.md с полными исходниками,
диспетчеры и проектные файлы. Он никогда не генерирует и не перезаписывает solutions/TaskNN.cs.
templates/Tasks.cs создаётся только при отсутствии файла: существующая самостоятельная работа сохраняется.
Не удаляйте заготовки ученика ради повторной генерации.

Смысловой дубль определяется входом, преобразованием и проверяемым навыком.
Новое имя, предметный сюжет или другие числовые константы сами по себе не создают новую задачу.
При повторении приёма в другой теме объясните новый результат обучения и дайте другой различающий тест.
Синтаксический fingerprint и сходство текста — сигналы для просмотра, а не доказательство эквивалентности.

Не добавляйте персональные данные, ключи доступа, локальные абсолютные пути и реальные пользовательские документы.
Решения должны работать без сети и создавать файловые примеры только в своих временных каталогах.
Внешние пакеты для обычных уроков не нужны; изменение пакетов итогового тестового проекта требует обновления lock-файла.

Учебные источники первичны; не изменяйте только сгенерированный Markdown.
Перед публикацией проверьте diff, сборку, прогоны и чистое получение GitHub-версии.
